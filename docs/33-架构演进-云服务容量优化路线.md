# 33-架构演进-云服务容量优化路线

> 目标：从"单机可跑"演进到"云服务 SaaS（用户多、数据大）"。
> 核心判断：当前单机架构在 10 万级数据/几十租户内健康，按数据增长曲线分四阶段推进，不一步到位。

## 演进路线（四阶段）

### 阶段一：单库优化（百万级内，零成本）—  已完成
- 大表按月分区：流水/日志/历史类只追加表（sys_oper_log、pf_oper_log、wf_task_history、bg_occupy、bank_reconcile）
- 慢 SQL + 索引治理：复合索引以 tenant_id 开头（多租户铁律）
- 冷热分层：ACT_HI 归档、报表预聚合、档案归档已铺垫

### 阶段二：读写分离 + 缓存 + 异步（千万级）
- MySQL 主从：报表/看板/审计查询走只读从库（rpt_summary 预聚合表已铺垫）
- Redis 集群：内存缓存升级为 Redis（多实例共享）+ 分布式锁 + 会话
- MQ 异步削峰：流程结束事件（WfProcessEndedEvent）同步收尾改异步，OCR/对账/验真入队

### 阶段三：分库分表（亿级，多租户 SaaS 关键）
- 租户分片：中小租户共享库（tenant_id 分表），大租户独立库；MyBatis-Plus 拦截器 + ShardingSphere
- 广播表：sys_menu/sys_dict_type_def/pf_* 每库一份；ACT_* 独立引擎库
- 租户配额：存储/API 并发/附件数限量

### 阶段四：云原生（多实例规模化）
- K8s 无状态扩缩（JWT 无会话已具备）
- 定时任务分布式调度（ShedLock/XXL-Job）防多实例重复执行
- 对象存储 OSS/COS 替换本地磁盘（存储根已配置化）+ CDN
- 可观测性：TraceId 全链路 + Prometheus + ELK + 租户级告警

## 阶段一落地明细（2026-08-13）

### 分区表（5 张，seed-p61）
| 表 | 分区列 | 说明 |
|----|--------|------|
| sys_oper_log | oper_time | 操作日志（量最大） |
| pf_oper_log | oper_time | 平台操作日志 |
| wf_task_history | oper_time | 任务历史 |
| bg_occupy | create_time | 预算占用流水（只增） |
| bank_reconcile | create_time | 银企勾对流（只增） |

- 主键改复合 (id, 时间列)；RANGE COLUMNS 预建 202601~202712 共 24 月 + pMAX 兜底
- 重建→拷贝→行数校验→换名→删旧；实测时间查询 `partitions: p202608` 单分区命中

### 不分区表（走归档）
exp_bill / op_voucher / op_voucher_line / exp_bill_payment：单列自增主键 + 按 id 高频 updateById，分区后按 id 查询全分区扫是负收益；改用结单归档（与档案归档衔接）。

### 分区维护
```sql
-- 新月份（每月月初）
ALTER TABLE sys_oper_log ADD PARTITION (PARTITION p202801 VALUES LESS THAN ('2028-02-01'));
-- 超期月份（秒删，替代 DELETE）
ALTER TABLE sys_oper_log DROP PARTITION p202501;
```

### 工具
- scripts/gen_partition_p61.py：SHOW CREATE TABLE → 主键加分区列 → 追加分区子句 → 生成 seed-p61.sql（可复用扩展新表）

## 建议优先级
1. 近期：阶段一收尾（慢 SQL 治理）→ 阶段二 Redis + MQ
2. 架构定型点：阶段三"租户分库策略"要早定（影响 pf/sys 表结构），实现可晚
