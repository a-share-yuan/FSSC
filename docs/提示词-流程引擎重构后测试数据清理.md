# 提示词:FSSC 流程引擎重构后测试数据清理

> 用法:整段复制给 AI 编码工具(在 FSSC 代码库上下文中执行)。
> 背景:流程引擎已重构,wf_* 表结构有增改;既有清理脚本 V9.9.9 基于旧的 230 张表,未覆盖新增的流程表和业务域。

---

## 任务

FSSC 财务共享系统流程引擎刚完成重构,需要把历史测试数据全部清干净(单据、待办、已办、流程实例与历史、附件、日志等),保留主数据和流程引擎配置数据,让系统恢复到"可以从零重新跑业务"的干净状态。

**只产出 SQL 脚本与清理报告,不改业务代码。**

## 工程事实(必须遵守)

- 代码库 `D:\SourceCode\Ashare\fssc`,MySQL 8,业务库 `fssc` + 影像库 `fssc_image`;
- 脚本风格:`SET FOREIGN_KEY_CHECKS=0` 包裹、子表在前父表在后、幂等可重复执行、末尾 `SET FOREIGN_KEY_CHECKS=1`;
- 多租户:清理脚本按全库清(所有 tenant),不按租户过滤。

## 执行步骤

### 1. 摸底
用 `information_schema.tables` 导出 `fssc` 与 `fssc_image` 两库当前全部表(含行数估计),与 `V9.9.9_cleanup_garbage_data.sql` 做差集:找出 V9.9.9 之后**新增的表**(已知至少有:`ap_service_request`、`ar_statement`、`ar_pre_invoice`、`ar_claim`、`ar_note`、`ar_mail_package`、`ar_writeoff_fund`、`ar_writeoff_record`、`ar_ebs_adjust`、`ar_recon_record`、`stock_move`、`stock_check`、`stock_check_line`、`stock_cost_settle`、`collab_scp_recon`、`collab_scp_bill`、`collab_ccp_shipping`、`collab_sync_log`、`pur_return`、`pur_return_line`、`sale_return`、`sale_return_line`、`fa_cer_request`、`ai_action_confirm`、`ai_inspect_rule`、`ai_tool_call_log`、`integration_call_log`、`sys_query_variant`,以及上列全部新 `wf_*` 表)。

### 2. 分类(产出"三类清单"给我确认后再执行)
对每张表归入三类,先产出清单待确认,**未经确认不得执行 DELETE/TRUNCATE**:

**A. 必须清理(黑名单)**
- Flowable 运行时+历史:`act_ru_*`、`act_hi_*`、`act_evt_log`,以及 `flw_ru_*` 等运行时表(与 V9.9.9 口径一致);
- 流程运行时数据:`wf_instance`、`wf_task`(待办)、`wf_task_history`(已办)、`wf_add_sign`、`wf_cc`、`wf_delegate`、`wf_approval_item`、`wf_process_log`、`wf_process_outbox`;
- 全部业务单据及子表:`exp_*`(报销/借款/差旅及冷归档)、`ap_service_request`、`ar_statement`、`ar_pre_invoice`、`ar_claim`、`ar_note`、`ar_mail_package`、`ar_writeoff_*`、`ar_ebs_adjust`、`ar_recon_record`、`rc_receivable`、`rc_receipt*`、`rc_collect_todo`、`rc_bad_debt`、`po_order*`、`po_receipt`、`pur_return*`、`sale_return*`、`cont_*`、`tr_*`、`pay_plan`、`stock_*`、`inv_*`(发票池)、`collab_*`、`supplier_recon*`、`bank_*`、`bg_adjust*`、`bg_occupy`、`bg_item`、`gl_*`(除 `gl_shared_master`)、`fa_cer_request`、`tax_refund`;
- 共享运营:`dispatch_task`、`op_audit_task`、`op_voucher*`、`op_pay_batch*`、`op_bank_statement`、`op_physical_delivery`、`op_barcode`、`op_job`、`op_job_heartbeat`、`op_review_log`、`op_quality`、`op_archive`、`op_gl_entry`、`precheck_result`;
- 资产/报表/审计/档案/影像/文件:`asset_depr_batch`、`rpt_summary`、`audit_reconcile`、`audit_trail`、`archive_*`、`fraud_detection_log`、`satisfaction_survey`、`image_review`、`image_exception`、`img_batch`、`img_file`、`sys_file`、`sys_file_token`;
- 日志/消息:`sys_oper_log`、`sys_login_log`、`sys_message`、`pf_oper_log`、`pf_login_log`、`pf_bill`、`pf_order`、`pf_tenant_stat`、`linku_sync_log`、`integration_call_log`、`ai_tool_call_log`、`sys_query_variant`;
- 编号序列重置:`TRUNCATE sys_number_seq`(编号**规则** `sys_number_rule` 保留);
- 遗留备份表:`DROP TABLE IF EXISTS` 形如 `*_bak_*` 的历史备份表。

**B. 必须保留(白名单,动到即停)**
- 主数据:`md_*` 全部;
- 系统与平台配置:`sys_menu/sys_role/sys_user_group/sys_user_group_rel/sys_role_menu/sys_dept/sys_post/sys_dict_*/sys_config/sys_number_rule`、`pf_tenant/pf_menu/pf_role/pf_role_menu/pf_user/pf_user_role/pf_package*/pf_order 配置类/pf_notice_template`;
- 流程引擎配置(重构后仍要用的):`wf_model`、`wf_business_flow`、`wf_node_config`、`wf_process_config`、`wf_flow_config`、`wf_assignee_dim`、`wf_assignee_scheme`、`wf_event_action_config`;
- Flowable 设计时:`act_re_*`(流程定义/部署)、`act_ge_property`、`act_ge_bytearray`、`act_id_*`、`act_procdef_info`;
- 业务规则配置:`ap_dispatch_rule`、`ar_dispatch_rule`、`ar_invoice_rule`、`ap_month_close 之外的费用政策`(`expense_policy*`)、`match_tolerance`、`md_match_tolerance`、`ext_interface_config`、`img_setting`、`bg_scheme`、`gl_shared_master`、`service_catalog`、`sod_*`、共享运营配置(`op_calendar/dispatch_rule/group/review_rule/voucher_template`)。

**C. 待确认(灰名单,单独列出等我拍板)**
- `crm_customer`(客户主数据;上次脚本曾整体清空,与"保留主数据"口径冲突);
- `sys_user` / `sys_user_role`(上次口径:保留 id<=10 核心用户、清理测试用户;是否沿用);
- `md_payee`(上次口径:保留前 10 条预置;是否沿用);
- `md_inventory` 等库存余额类(清零还是保留);
- `ap_month_close` / `ar_month_close` / `gl_month_close`(月末关账状态,清空=重置为未关账,是否同意);
- `tax_declaration` / `tax_input_certify` / `tax_risk_indicator` / `employee_credit` / `reviewer` / `precheck_result` 等归属存疑的表(判定为单据数据还是配置);
- `fssc_image` 影像库的表,以及磁盘物理文件目录(`fssc-server/data/files`、`upload/`)是否同步清理;
- `flw_channel_definition` / `flw_event_definition` 等 Flowable 事件定义表(上次脚本做了 TRUNCATE,重构后是否能重部署,需确认)。

### 3. 备份
执行前先用 `mysqldump` 全量备份 `fssc` 与 `fssc_image`(文件名带日期,放 `db/backup/` 下),备份成功才允许继续。

### 4. 产出脚本
`fssc/sql/V9.9.12_cleanup_after_wf_refactor.sql`(版本号按 `fssc/sql/` 目录现状顺延):
- 分节注释(Flowable/流程/单据/共享运营/日志/序列重置),风格对齐 V9.9.9;
- 幂等:`CREATE TABLE IF NOT EXISTS` 不适用时用 `DROP ... IF EXISTS`、TRUNCATE 天然幂等;
- 脚本头部用注释列出三类清单的最终决策结果(作为留痕)。

### 5. 验证
- 产出独立验证 SQL:清理前后各表行数对比;白名单表行数前后一致断言;孤儿检查(`wf_instance` 为 0 时,所有业务单据表必须为 0;`sys_number_seq` 为 0 而 `sys_number_rule` 行数不变);
- 在 dev 库执行 → 重启 `fssc-start` → 冒烟:能登录;发起一条报销或应付流程,提交→审批通过后"已办"可见、"待办"清零;新建单据编号从 0001 重新开始。

### 6. 清理报告
输出 Markdown 报告:清理表数与行数统计、保留表行数、灰名单决策记录、冒烟结果、遗留风险(如影像物理文件、BCP 侧残留引用)。

## 红线

1. 白名单表一律不碰;发现清理表对白名单表存在外键引用时,先报告方案,不得直接删;
2. 灰名单未确认前不执行;
3. 不修改任何 Java/Vue 代码;
4. 脚本必须可在已清空的库上重复执行不报错、不产生副作用。
