# 业务流程：应付管理

应付链路的灵魂是**三单匹配**：采购订单、收货单、发票三方对得上才放行付款，
对不上精准指出差在哪。这是共享中心"敢集中付款"的底气。

> **档案模式提示**：付款单据同样受公司档案模式影响。集中模式下对公付款单据需扫描并实物签收，
> 签收后共享审核链才激活；非集中模式无扫描/签收环节，交付状态恒为 `NOT_REQUIRED`，
> 付款审批改走 `SETTLE_NC`。完整对照见
> [档案集中与非集中管理模式](业务流程-档案管理模式.md)。

## 1. 流程总览

```
[采购订单 po_order] ──┐
[收货单 po_receipt] ──┼──► [三单匹配 match] ──不齐──► 拦截+差异清单
[发票 inv_invoice] ──┘        │齐
                              ▼
[结算单 tr_bill_settle] → [SETTLE 审批] → [出纳组批 op_pay_batch]
                                                    ↓
[TR_PAY 资金付款审批] → [银行执行] → [付款凭证] → [付款凭证推送(外部ERP可选)]
```

## 2. 环节详解

### 2.1 三单匹配（match 域）
- 匹配键：物料/服务项 + 数量 + 单价 + 金额；
- 容差可配（`match_tolerance`：金额差/税率差/数量差各档处理：放行/预警/拦截）；
- 差异清单逐行列出"订单有收货无发票""发票金额超订单 X%"等，不是笼统失败。

### 2.2 结算单（tr_bill_settle）
- 汇总匹配通过的明细生成结算单，付款条件来自合同（`cont_pay_condition`）；
- 流程 `SETTLE` 审批：按金额/公司走不同审批链。

### 2.3 出纳组批（sharing/payplan 域）
- 按付款计划（`pay_plan`）或即时需求组批（`op_pay_batch`）；
- 批次内明细（`op_pay_batch_detail`）带收款方账户（`md_payee`）；
- 批次支持拆分/合并，资金头寸不足时提示。

### 2.4 资金付款（treasury 域）
- 流程 `TR_PAY`：确认 → 执行两档，附件齐套闸口把关；
- 银企通道执行（默认 mock；真实接银企直连走 SPI + 凭据环境变量）；
- 执行结果回写：成功/失败/退票，失败自动挂起并通知。

### 2.5 凭证与推送
- 付款成功生成付款凭证（借贷平衡校验）；
- 可选推送外部 ERP（`op_voucher_push_log` 留痕，令牌走环境变量）。

## 3. 关键表

| 表 | 作用 |
|---|---|
| `po_order`/`po_order_line` | 采购订单 |
| `po_receipt` | 收货单 |
| `inv_invoice`（进项） | 发票（票号段演示库 `047219xx`） |
| `tr_bill_settle` | 结算单 |
| `op_pay_batch(_detail)` | 付款批次 |
| `match_tolerance` | 匹配容差配置 |

## 4. 与 BCP 协同

- 供应商可在 BCP 门户确认结算单、上传发票（`collab_scp_*`）；
- 协同单据状态回写 FSSC，无需双方重复录入；
- BCP 降级模式下走本地导入兜底。

## 5. 排障速查

| 现象 | 先查 |
|---|---|
| 匹配不过 | 容差配置 + 差异清单逐行 |
| 付款执行失败 | 银企通道 mock/真实 + 账户状态 + 头寸 |
| 批次审批人不对 | TR_PAY 流程 node_key + 取人白名单 |
| 结算单卡住 | 齐套闸口缺的附件清单 |
