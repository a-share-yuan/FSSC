### 1.2 缺陷定性

**这是与 `MyDelegate.vue` 的 `EXPIRED` 分支完全同型的缺陷**：

> 前端与读端 100% 就绪 → 后端生产端 0% → 数据恒为 0 → 页面永远显示"暂无抄送"，
> 且由于页面本身正常工作（空态），**从表象上完全看不出功能没做**。

比 `MyDelegate` 更严重的一点：`MyDelegate` 至少有表有列（只是状态列永无写入点），
而 G2 **连"抄送给谁"的配置入口都不存在**（`wf_node_config` 无任何抄送列）。

### 1.3 附带发现：`nodeType='CC'` 是悬空 UI

`FlowConfig.vue:350` 的「节点类型」下拉里有 `<el-option label="抄送" value="CC" />`，
**但 `wf_node_config` 表根本没有 `node_type` 列**，后端 grep 到的 `getNodeType()` 全部是
XML DOM 的 `org.w3c.dom.Node.getNodeType()`，与此字段无关。

⇒ 该字段**既不落库也不被消费**，选「抄送」不会产生任何抄送记录。已在界面上就地标注。

## 3. G3 已办撤销：只读预览（新增）

### 3.1 为什么只做预览

Flowable **8.0.0 没有 `ProcessInstanceModification`**（javap 核对 `flowable-engine-8.0.0.jar` 确认），
等价原语是 `ChangeActivityStateBuilder.moveActivityIdTo` —— 它属「**搬执行**」：直接把运行中的
执行实例挪到目标活动，**会真实改动在办单据本体**（作废既有任务、重放历史流转）。

改错破坏的是**单据本身**，不是日志。而当前 8089 已停、**无任何运行期验证手段** ⇒ 盲改不可接受。

### 3.2 实现内容（严格只读、零副作用）

| 层 | 内容 |
|---|---|
| Service | `WfEngineFacade.withdrawPreview(procInstId)` — 组装单据信息 + 引擎真实态在办任务 + 可回退节点及影响面 |
| 入参解析 | `procInstIdOfTask`（含已办结任务，退回历史表）+ `resolvePreviewTarget`（实例ID/任务ID **自动识别** —— 两者都是数字串，无法按格式区分） |
| 开关 | `isDoneWithdrawEnabled()` 读 `sys_config.wf.withdraw.done.enabled`，**fail-closed**（读不到即关） |
| 端点 | `GET /api/tenant/wf/withdraw-preview?procInstId=&taskId=&keyword=` |
| 前端 | 新页 `views/workflow/WithdrawPreview.vue` + 路由 `flow-center/withdraw-preview` + `FlowCenter.vue` 入口（权限 `wf:instance:list`） |

**口径定义**：可回退节点 = 链上「已办」节（`DONE`/`REJECTED`）。语义取「**退回到该节点重办**」：
该节点本身需重办，其后所有节点（含未到达的 `TODO`）都会被作废后重新流转。影响面逐节点列出。

**数据来源**：`wfQueryService.chain()`（已过/当前/待到达的唯一真相源）+ 引擎 `TaskQuery.active()`
（不信 `wf_task` 镜像 —— 镜像有滞后缺陷史）。
