# 业务流程：影像与发票

影像域解决"纸质附件电子化"，发票域解决"票真假与抵扣"。
两者通过 `exp_bill_receipt`/`inv_invoice` 与业务单挂接，是审计取证的关键腿。

> **档案模式提示**：集中管理模式下纸质原件寄送共享中心，由扫描岗在流程首节点采集影像；
> 非集中管理模式（`NON_CENTRAL`）原件留在原单位，影像由业务端上传电子附件/扫描件，
> 不经过共享中心扫描岗、也不产生实物签收。影像与 OCR 能力本身两种模式通用，
> 差异只在采集入口与归档前置条件。完整对照见
> [档案集中与非集中管理模式](业务流程-档案管理模式.md)。

## 1. 影像流程总览

```
[扫描/上传] → [采集批次 img_batch] → [OCR 识别 ocr_record]
                                              ↓
[人工复核 image_review] ← [异常 image_exception] ←┘
        ↓
[挂接业务单据] → [装订 op_archive] → [借阅/销毁审批] → [归档]
```

## 2. 环节详解

### 2.1 采集批次（image 域，独立库 fssc_image）
- 影像存独立库（6 张表），与主库物理分离，便于存储扩容与备份策略差异化；
- 批次（`img_batch`）按来源/时间归集，文件（`img_file`）带页数/格式/大小。

### 2.2 OCR 识别（可插拔通道）
| 通道 | 配置 | 场景 |
|---|---|---|
| mock | `FSSC_OCR_CHANNEL=mock` | 离线演示，确定性票面 |
| gateway | `INVOICE_GATEWAY_*` | 对接发票能力网关（默认 8096） |
| paddle | 本地 PaddleOCR 微服务 | 内网私有化 |
| http | `sys_config` 配端点 | 任意真引擎 |

- 识别结果落 `ocr_record`：票号/金额/税额/买卖双方/品类；
- 低置信度或字段缺失进异常队列（`image_exception`）。

### 2.3 人工复核
- `image_review`：复核人对 OCR 结果确认/修正，修正留痕；
- 复核通过才允许挂接业务单据。

### 2.4 发票查验（invoice 域）
- `inv_verify_log` 记录查验动作与结果（演示环境为模拟）；
- 发票状态机：待查验→已查验→已抵扣→已红冲。

### 2.5 档案（document 域）
- 装订（`op_archive`）：业务单 + 影像按档案号装册；
- 借阅/销毁有审批流（`archive_destroy_approval`），借阅留痕（`archive_access_log`）。

## 3. 与业务域的挂点

| 业务动作 | 影像要求 |
|---|---|
| 报销提交 | 票据影像挂接（齐套闸口检查） |
| 应付结算 | 发票影像 + 三单匹配 |
| 收款登记 | 承兑票据影像 |
| 月结 | 必传附件齐套性检查 |

## 4. 演示路径

上传一张演示发票图片 → 批次自动 OCR → 复核确认 → 挂到报销单 →
走完报销 → 档案装订 → 借阅申请。

## 5. 排障速查

| 现象 | 先查 |
|---|---|
| OCR 不出字段 | 通道配置（mock 不需要外网） |
| 影像挂不上单据 | 复核状态/齐套闸口缺失清单 |
| 找不到历史影像 | 冷归档（`*_cold`）与借阅日志 |
