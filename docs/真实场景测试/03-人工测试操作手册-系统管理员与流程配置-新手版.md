## 三之二、填表没反应？先看这六类原因系统管理面最常见的“点了没反应”，按下面顺序排查，不要一上来就判缺陷：

1.  **权限点没授予**：页面能看见，按钮点了返回 「缺少权限」：xxx。先查第十四节的“无角色持有”清单；在清单里的，是权限缺口，记录后跳过。
2.  **菜单授权与接口权限分离**：角色有接口权限但没有菜单，左侧看不到入口。可地址栏直输验证；直输能开说明是菜单没授，不是页面坏了。
3.  **公司范围不匹配**：角色是 COMPANY 范围，但账号在别的公司；候选人、数据列表都会为空。
4.  **浏览器拿了旧缓存**：刚发版后旧 chunk 还在。强刷 Ctrl+F5 或开无痕窗口再试一次。
5.  **后端还是旧包**：页面改了、接口没上。看运行状态页的构建时间/版本，和发版记录对不上就停手。
6.  **受控数据重名**：DEMO 测试数据重复新增会撞唯一键。先查询再新增；**已存在＝上一轮没退役** ⇒ 停下找系统管理员，由他在清理窗按对应分册七之四 节「DEMO 族退役」清零后重开。测试人不要自己删旧行，也不要“换个后缀绕键”（换了后缀，本册后续步骤与台账点名的名称就对不上）。

## 十二、FAQ

**Q：某个分组下只看到 1 项，手册写的子菜单少了一个？** 要分清两件事：**① 分组名整个消失**＝该分组在你账号下只剩一个条目，前端自动收敛成那一项（设计如此，见册首说明，不要当缺陷）；**② 手册列了 3 项你只看到 1 项**＝**授权缺口**，与收敛无关。复核口径（只读）（这条只读核对语句收在附录 C）

**Q1：为什么用 admin 做配置，不用 100083？** 因为本次普查发现 151 个权限点没有角色持有；用户、角色、组织、职位、期间结账、流程节点、大部分主数据修改都只能由 admin 完成。100083 只验证“页面能看、字典/供应商能写”，全局参数由 admin 写。这不是让 admin 长期运维，而是本次测试的核对方式。

**Q2：100083 打开角色管理被拦，是缺陷吗？** 不是。system:role:\* 没有任何角色持有，角色管理菜单也没有授给任何业务角色；admin 账号的 用户档案.=1，后端按超级管理员放行。记录“非 admin 被拦”即可。若 admin 也打不开，才是缺陷。

**Q3：流程配置页顶部蓝色提示是什么？** 是“页签被权限裁剪”的说明。100122 没有 wf:node:list，节点配置页签不显示；委托代理页签也不显示，但 wf:delegate:list 实际由多个角色持有，只是 流程管理员 未持有。（较新的版本里这条提示会把缺的权限名一并点出来）。运行实例页签可见。记录为权限缺口，不要改库授权。

**Q4：发布受控模型会不会影响业务？** 不会。DEMO 的 bizType 是 DEMO，没有任何业务代码用它发起流程；模型也没有绑定到真实 bizType。发布后只是多一条可查询的模型记录。不要把它绑定到报销单据、 等真实类型。

**Q5：校验有 warning 能不能发布？** 可以，但要在记录表抄下 warning 内容。有 error 必须停，不能硬发布。模拟要看接口 trace 是否有完整路径；修复后界面 3 行均显示节点名与审批人，仍建议与接口 trace 逐行对照。

**Q6：页面数字和起点对不上怎么办？** 先确认筛选条件、公司范围、时间范围是否一致；再看是否有人同时在测。排除后仍不一致，报成缺陷并把两个数字都抄下来。不要为了让数字对上而改数据。

**Q7：按钮点了 权限拦截，但页面还能用，算不算缺陷？** 分两种：该角色本来就不该有写权限，被拦下是正确行为，不算缺陷；该角色按设计应该有写权限（页面授权了此按钮/菜单），却仍然被拦下，算缺陷。对照标准是本册第十四节的“权限缺口清单”与角色授权表。本次曾登记编号规则/公告管理写按钮未按权限码门控，修复后 100083 已看不到写按钮；若复跑仍能看到，按“按钮在但无权限”报成缺陷，不要点保存，也不必据此认为授权完整。

**Q8：能不能把测试用户/角色/模型删掉？** 不能。本册遵守“不删任何数据”。DEMO 前缀就是留给后续识别用的；收工时在记录表注明“受控数据保留”＝本次留证。要按同一批名称重跑，由系统管理员按对应分册七之四 节「DEMO 族退役」在清理窗退役 DEMO 族后重开，测试人不要自己删库。

**Q9：能不能改 approve.连办控制参数 之类的参数让流程跑通？** 不能。参数是起点的一部分；改参数等于改被测对象。流程跑不通就报成缺陷，不改配置。

**Q10：BCP 异议审核页要不要点？** 本册只验证该页能否打开、列表是否正常；不发起 BCP 流程、不等待 BCP 回写、不改 BCP 数据。BCP 系统不在本册范围。
