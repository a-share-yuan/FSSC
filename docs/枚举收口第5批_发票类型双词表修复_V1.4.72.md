# 枚举收口第 5 批：发票类型「双词表」缺陷修复（V1.4.72）

> 日期：2026-10-16　｜　范围：前端 `constants/invoiceType.js`、`constants/enums.js`、字典 `enum_invoice_type`
> 性质：**真实缺陷修复**（不是理论收口）——修的是"同一条数据下拉一套词、列表另一套词"以及"8 类票据直接显示英文码"

---

## 1. 缺陷：同一份数据，两处两套词

前端存在**两份互不引用**的发票类型词表：

| # | 位置 | 键数 | 用途 | `VAT_SPECIAL` 的中文 |
|---|------|------|------|---------------------|
| ① | `constants/invoiceType.js` → `INVOICE_TYPES` | 13 | el-select **下拉选项** | `增值税专用发票` |
| ② | `constants/enums.js` → `INVOICE_TYPE` | 8 | `enumLabel()` 取**表格/详情**中文 | `增值税专用` |

第 4 批（V1.4.71）只把 ② 灌成了字典 `enum_invoice_type`（9 行），① 仍是硬编码，于是：

- **后果 A（两套词）**：下拉选「增值税专用发票」存库后，列表列经 `invoiceTypeLabel()` 显示成「增值税专用」——同一条数据，两处两样。
- **后果 B（英文码）**：高铁 / 火车票 / 机票 / 出租车 / 网约车 / 定额 / 停车 / 医疗 **这 8 类在 ② 里根本没有**，
  `enumLabel` 兜底把 `RAIL_HIGH`、`RIDE_HALLING`、`QUOTA`、`MEDICAL` 等**英文码直接显示给用户**。
- **调用面**：`Invoice.vue` 走 ②（`import { invoiceTypeLabel } from '@/constants/enums.js'`），
  而 `ArBillingBoard` / `ArApCollabBoard` / `ImageManager` / `OcrRecords` 四页走 ①（`from '@/constants/invoiceType'`）
  —— 同一个函数名、两条不同的词表。

## 2. 权威源裁定：以 `invoiceType.js` 为准

后端 `OcrLocalParsers` 的常量恰为 **13 型**，且源码注释明写「编码与前端 `constants/invoiceType.js` 对齐」：

```java
public static final String T_VAT_SPECIAL  = "VAT_SPECIAL";   // 增值税专用发票
public static final String T_RAIL_HIGH    = "RAIL_HIGH";     // 高铁/动车
... T_TRAIN / T_AIR / T_TAXI / T_RIDE_HALLING / T_QUOTA / T_TOLL / T_PARKING / T_MEDICAL / T_OTHER
```

⇒ ① 与后端对齐、是权威；② 是**没跟上 OCR 扩展的过时残本**。

顺带裁掉一处真冲突：

| 码 | `enums.js` ② | `invoiceType.js` ① LEGACY | 采纳 |
|----|--------------|---------------------------|------|
| `VAT` | 增值税**普通** | 增值税**专票** | ①（与后端 `ScpReconService` 归一化逻辑一致：`增专→VAT_SPECIAL`、`增普→VAT_NORMAL`，故 `VAT` 与 `VAT_SPECIAL` 同族） |

## 5.  方法论结论（本批最有价值的产出）

为找同类问题写了全量审计脚本 `scripts/_audit_enum_conflict.py`（扫 `label/value` 对、三元 formatter、Map 字面量），
结果推翻了"同码不同词 = 缺陷"这个直觉：

**同一个码在【不同业务域】本来就该不同：**

| 码 | 域 A | 域 B | 域 C |
|----|------|------|------|
| `IN` | 现金流量码＝**流入** | 收支设置＝**收入** | 字典 `enum_direction`＝**入库** |
| `AIR` | 发票类型＝**航空运输电子客票** | 交通方式 `trafficTypeLabel`＝**飞机** | `enums.js`＝机票 / 机票结算 |
| `AP` | 应付 | 应付组 | — |
| `OUT` | 流出 | 支出 | 出库 |

⇒ **字典必须「按业务域建」，绝不能跨域复用同一个 `dict_type`。**
这也是 V1.4.71 用 `enum_<容器名>` 命名的隐含前提——它天然按容器（域）隔离。

⇒ 该审计脚本的 `CONFLICT` / `MISSING` **不是缺陷清单**，只是"待字典化候选"。
**真正会回显英文码的，只发生在共享取词路径**（`enumLabel` / `statusLabel` / `invoiceTypeLabel`）**背后常量缺键时**
——本批发票类型是迄今实证到的唯一一例。页面自带 `{label,value}` 词表的 `MISSING` 项显示正常。

该口径警告已写进脚本头部注释与项目 MEMORY.md。
