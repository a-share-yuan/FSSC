# 业务流程：应收管理

应收链路把"客户欠什么、收了什么、还差多少"管到底：对账 → 开票 → 应收确认 →
收款核销 → 坏账。与 BCP（产业链协同）对接时，客户可在门户协同确认。

## 1. 流程总览

```
[对账 ar_statement] → [开票 INVOICE_ISSUE] → [应收确认 RECEIVABLE]
        ↓                                            ↓
[客户协同确认(BCP)]                          [收款 rc_receipt]
                                                      ↓
[核销 rc_receivable] → [账龄/催收 rc_collect_todo] → [坏账 rc_bad_debt]
```

## 2. 环节详解

### 2.1 对账（ar_statement / ar_recon_record）
- 按客户/期间生成对账单，明细来自销售出库（`so_shipment`）与服务记录；
- 差异落 `ar_recon_record`，支持多轮对账留痕；
- BCP 模式下客户在门户确认（`collab_ccp_*` 协同单据）。

### 2.2 开票（invoice 域）
- 开票规则按客户配置（`ar_invoice_rule`：票种/税率/限额外）；
- 流程 `INVOICE_ISSUE` 驱动开票审批；
- 票据落 `inv_invoice`（销项），票号段管理（演示库 `147219xx` 段）。

### 2.3 应收确认（receivable 域）
- 已开票未收款部分转 `rc_receivable`，账龄起算；
- 确认流程 `RECEIVABLE`，可按客户信用（`employee_credit`/客户信用级）走不同链。

### 2.4 收款与核销
- 收款登记 `rc_receipt`/`rc_receipt_line`（可多笔收款一张单核销）；
- 核销：按金额/按单据，核销记录可反冲；
- 预收（`tr_credit_bill` 应收票据）到期转收款。

### 2.5 催收与坏账
- 账龄自动分档，生成催收任务（`rc_collect_todo`）；
- 坏账计提/核销走 `rc_bad_debt`，需审批并留痕。

### 2.6 月结（arflow 域）
- `ar_month_close`：检查未对账差异、未核销收款、坏账计提完整性后方可关账。

## 3. 关键表

| 表 | 作用 |
|---|---|
| `ar_statement` | 对账单头 |
| `ar_pre_invoice` | 预制发票（开票前） |
| `inv_invoice` | 发票主表（销项） |
| `rc_receivable` | 应收台账 |
| `rc_receipt` | 收款单 |
| `rc_bad_debt` | 坏账处理 |
| `ar_writeoff_record` | 核销记录 |

## 4. 与应付/资金域的接口

- 收款登记后回写 `bank_balance`/银行流水，参与对账；
- 坏账、核销差异生成总账凭证（`gl_book_voucher`）；
- 客户主数据来自 `crm_customer`（customer_type=CUSTOMER）。

## 5. 演示路径

对账单生成 → 客户协同确认 → 开票审批 → 应收确认 → 收款登记 → 核销 →
凭证查询看到结转分录 → 月结检查通过。
