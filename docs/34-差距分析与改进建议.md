## 二、核心差距分析（按严重程度排序）

###  P0级差距（影响合规性和核心流程）

#### 2.1 缺少费用政策管理模块

> ** 现状核对（2026-08-19）：部分覆盖。** 已有报销标准（差旅/住宿标准+超额标记 overStd）、借款额度配置、单笔上限/发票必附全局参数；缺集中化政策配置与提交时限规则。

**问题描述**：当前项目缺少独立的费用政策管理功能，无法集中管理各部门/各费用类型的审批规则、金额阈值、差旅标准等。

**行业标准**：
- 财政部指引第13条要求"会计政策标准化、业务场景标准化、审核规则标准化"
- 皖北煤电操作手册中明确区分不同费用类型的处理规则
- 行业最佳实践：200+条智能审核规则，90%自动通过率

**需要补充的功能**：
```
┌─────────────────────────────────────────────────────┐
│              费用政策管理模块                        │
├─────────────────────────────────────────────────────┤
│ 1. 费用类型规则配置                                  │
│    - 差旅费（住宿/交通/餐饮标准）                    │
│    - 招待费（客户类型/金额上限）                      │
│    - 会议费（场所/人数/单日标准）                     │
│    - 培训费（类型/金额/审批路径）                     │
│    - 通讯费（月度限额/实报实销）                      │
│    - 办公用品（单笔/月度限额）                       │
│                                                     │
│ 2. 审批规则引擎                                     │
│    - 按金额阈值自动路由                              │
│    - 按部门/项目差异化审批                            │
│    - 超标附加审批流程                                │
│    - 重复报销检测                                    │
│                                                     │
│ 3. 差旅标准管理                                     │
│    - 按员工等级的交通/住宿/餐饮标准                   │
│    - 国内/国际差旅标准                               │
│    - 超标申请流程                                    │
│                                                     │
│ 4. 提交时限规则                                     │
│    - 费用发生后14-30天内提交                         │
│    - 逾期需额外审批                                  │
└─────────────────────────────────────────────────────┘
```

#### 2.2 缺少合规预检引擎

> ** 现状核对（2026-08-19）：部分覆盖。** 已有分散校验：发票必附、报销标准检查、预算占用、发票唯一键查重（uk_tenant_inv）、借款额度；缺提交时 9 维度一次性预检反馈。

**问题描述**：当前预算检查和发票验真是基础检查，缺少完整的前置合规校验逻辑。

**行业标准**：
- "规则引擎实时校验发票真伪、费用标准、预算余额，不合规项立即驳回"
- "将风险前置"理念：提交时即时反馈所有不合规项
- IRS要求：业务关联、金额佐证、超额退还三要素验证

**需要补充的校验规则**：

| 校验维度 | 具体规则 | 触发时机 |
|---------|---------|---------|
| 发票真实性 | 增值税发票在线验真 | 提交时实时 |
| 发票重复性 | 查重检测（金额+税号+日期） | 提交时实时 |
| 发票合规性 | 抬头、税号、金额一致性 | 提交时实时 |
| 预算合规性 | 预算科目、额度、期间检查 | 提交时实时 |
| 标准合规性 | 差旅/招待/会议等费用标准 | 提交时实时 |
| 业务关联性 | 是否关联事前申请/合同/项目 | 提交时实时 |
| 单据完整性 | 必填项、附件、签字检查 | 提交时实时 |
| 时间合规性 | 费用发生与提交时间差 | 提交时实时 |
| 人员合规性 | 经办人权限、部门归属 | 提交时实时 |

#### 2.3 缺少自动派单与共享作业池机制

> ** 现状核对（2026-08-19）：已实现基础作业池。** 审批通过 → SharingService.createAuditTask 自动入池（WAITING）→ 认领（receive）→ 完成（finish 自动激活下一环节），作业链为"票据审核→付款审核→记账归档"。待补：按金额/业务类型/地区的**智能派单**（当前为抢单式）、超时升级。

**问题描述**：当前审核流程是固定的线性流转，缺少动态派单和智能分配。

**行业标准**：
- "系统根据费用类型、金额、地区等因素，自动分配至共享中心审核人员"
- "按业务类型、复杂程度和风险等级建立作业池"
- 财政部指引要求"持续优化流程，实现高效、规范运转"

**需要补充的机制**：
```
┌───────────────────────────────────────────────────────────────┐
│                    智能派单引擎                                │
├───────────────────────────────────────────────────────────────┤
│                                                               │
│  派单维度：                                                    │
│  ├── 按业务类型：差旅费→A组，招待费→B组，会议费→C组            │
│  ├── 按金额等级：≤5000→初级审核，5000-50000→中级，>50000→高级  │
│  ├── 按法人主体：不同分公司分配给对应审核组                    │
│  ├── 按复杂度：涉及合同/项目→专项审核组                       │
│  └── 按地区：跨地区业务→对应地区审核组                        │
│                                                               │
│  派单策略：                                                    │
│  ├── 轮询分配（Round-Robin）                                  │
│  ├── 负载均衡（按当前待处理数量）                              │
│  ├── 专长匹配（按审核员技能/历史准确率）                       │
│  └── 手动干预（主管调整）                                     │
│                                                               │
│  异常处理：                                                    │
│  ├── 超时升级（超过4小时自动升级）                             │
│  ├── 退回重派（审核员拒绝后自动重分配）                         │
│  └── 批量处理（同类单据批量审核）                               │
│                                                               │
└───────────────────────────────────────────────────────────────┘
```

#### 2.4 缺少电子会计档案归档模块

> ** 现状核对（2026-08-19）：已实现。** ArchiveService：待归档清单（审批完成+影像完整）→ 归档执行（文件迁移 archive 区 + 生成档案记录 + 单据标记 ARCHIVED）+ 档案调阅页 + **每天 2:00 定时自动归档**。待补：档案销毁提醒（P1）、归档完整性自动校验。

**问题描述**：当前影像管理覆盖了影像采集和审核，但未实现凭证+影像的自动归档和档案管理。

**行业标准**：
- 财政部指引第4条明确将"会计档案管理"列为基本服务
- "凭证生成后，电子会计凭证与报账单、实物票据影像一起归档"
- 国家《电子会计档案管理规范》要求电子档案与纸质档案具有同等法律效力

**需要补充的功能**：

| 功能 | 说明 | 优先级 |
|-----|------|-------|
| 自动归档 | 凭证审核通过后自动归档单据+影像+凭证 | P0 |
| 档案检索 | 按单据编号/期间/部门/经办人多维检索 | P0 |
| 档案调阅 | 审批后查看档案原始影像 | P0 |
| 档案销毁 | 按保管期限到期提醒销毁 | P1 |
| 完整性校验 | 归档时校验影像与凭证一致性 | P0 |
| 跨系统同步 | 与公司档案系统对接 | P1 |

#### 2.6 缺少智能审单引擎

> ** 现状核对（2026-08-19）：已实现。** SmartReviewService 规则引擎 + op_review_rule 规则表（预置 5 条 DEMO1 规则）；审批通过进入共享作业池前自动裁决：命中高风险欺诈→AUTO_REJECT 驳回、小额合规→AUTO_PASS 自动通过、大额/超标/无票→MANUAL_REVIEW 转人工。前端 智能审单规则 / 审单日志 / 统计 页面已接入。

**问题描述**：当前审核依赖人工判断，缺少规则驱动的自动审核能力。

**行业标准**：
- "利用NLP与图像识别，自动提取报销单关键信息，并与业务逻辑比对"
- "90%的报销单可自动通过审核，仅10%特殊场景需人工介入"

**需要补充的审核规则**：

| 规则类别 | 具体规则 | 自动化级别 |

| 预算规则 | 科目、额度、期间、冻结状态 | 100%自动 |
| 标准规则 | 差旅标准、招待标准、会议标准 | 90%自动 |
| 业务规则 | 事前申请关联、合同关联、项目关联 | 80%自动 |
| 合规规则 | 提交时限、人员权限、部门归属 | 95%自动 |
| 反欺诈 | 高频异常、金额凑整、跨区域、供应商异常 | 60%自动(需人工复核) |

###  P2级差距（优化提升）

#### 2.8 缺少反欺诈与风控模型

> ** 现状核对（2026-08-19）：已实现。** FraudDetectionService 多维度检测（高频/金额凑整/跨区域/供应商异常/节假日/同供应商/供应商风险/类型金额错配等）+ fraud_detection_log 落库；单据提交时实时扫描（不阻断提交，仅记录风险）；前端 反欺诈检测记录 / 汇总 页面已接入。

**行业标准**：
- "基于历史数据训练异常检测算法，实时识别高风险行为（如频繁更换酒店、金额异常凑整）"
- "合规风险降低90%"

**建议补充**：
- 高频行为检测（同一经办人短期内多次报销）
- 金额异常检测（金额凑整、接近阈值）
- 供应商关联检测（与供应商有历史关联）
- 地理位置异常（出差地点与业务不符）
- 时间异常（非工作时间提交、节假日高额消费）
