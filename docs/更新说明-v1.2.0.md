# FSSC v1.2.0 更新说明

版本范围：后端 `fssc-server` / `fssc-common` / `fssc-start` 与前端 `fssc-web` 统一为 **1.2.0**；演示库 `db/Dump20261104/` 已刷新。

---

## 一、这个版本解决的核心问题

v1.1.1 之前有一批「能力做了一半」的功能：后端有接口、前端没入口；或界面上有正向按钮、没有反向按钮。结果是业务卡住时只能改库。本版把它们逐个补齐。

| 能力 | 之前 | 现在 |
| --- | --- | --- |
| 预算行冻结 | 只有接口，界面既不能冻结也不能解冻 | 列表有状态列与冻结/解冻按钮，两个方向都要求填原因并写审计 |
| 公司 / 部门启停用 | 接口存在，前端 0 调用 | 组织树节点上直接启停；后端补三道自锁（当前登录主体、最后一家公司、未停用子节点/在职用户） |
| 合同关闭 | 只能关不能开 | 新增重开（CLOSED→EFFECTIVE，并重新占用关闭时释放的预算） |
| 采购订单终止 | 落 VOID 即锁死 | 新增恢复（回 DRAFT 重走审批；已收货单拒绝） |
| 智能审单规则 | 表单缺动作字段，配了不生效；只能删不能停 | 表单补齐编码/动作/优先级/适用单据类型；启停开关恢复 |
| 质检扣分 | 前端走的路径只入库、不扣分 | 两条路径口径统一 |
| 信用免审 | 建档从不发生，体系起不来 | 铺底 452 人；门槛、等级、抽检三参数可调 |
| 预检拦截 | 只在内存算完抛异常，拦了什么无记录 | 落 `precheck_result`，新增「预检漏拦分析」看板 |

## 二、新增的两块度量

**预检漏拦分析**（`/compliance/precheck-stats`）

- 按规则码统计拦截次数与涉及单据，暴露长期 0 命中的规则（条件写错或被别的规则覆盖）；
- 漏拦率＝质检退回中、预检当期没有 FAIL 记录的比例，附前 50 条样本。

度量对象是**系统规则的缺口**，不是员工。

**信用免审三参数**（`sys_config`，改完即时生效，无需重启）

| 参数 | 缺省 | 作用 |
| --- | --- | --- |
| `review.credit.auto_approve.enabled` | `1` | 置 0 只累计信用、不放行 |
| `review.credit.auto_approve.min_level` | `B` | 低于该档一律人工；新员工 600 分是 C 级，不免审 |
| `review.auto_pass.sample_rate` | `0.10` | 自动通过的单据按该比例转人工复核（免审≠不查） |

## 三、口径修正

- **信用分不再有死循环**：规则命中「自动通过」也给 +5。原先只有「信用免审通过」才加分，而免审又要求 B 级，新员工永远停在 C 级。
- **违规扣分只收行为类**：发票真伪、重复报销、作废红冲分别由预检硬拦截、`verify_status` + 异常巡检、`VOID`/`RED_FLUSHED` 状态处理，**不计入员工信用**。机器能判的不该让员工背锅；纸质票时代的「粘贴单据规范」废弃。
- **金额分档不在审单规则里做**：`CLAIM` 流程已有四个金额网关（5 万/20 万/50 万/500 万 → 基地财务经理/基地总经理/板块财务经理/总裁）级联加签，审单规则只做「过/驳/转人工」。

## 四、升级方式

二选一：

1. **重新导入 dump**（推荐，最省事）：按 `db/README.md` 导入 `db/Dump20261104/`；
2. **原地增量**：按 `db/upgrade/README.md` 顺序执行 `V1.6.19` ～ `V1.6.26`。

本次新增的增量脚本：

| 版本 | 内容 |
| --- | --- |
| `V1.6.21` | 预算冻结/解冻权限点 |
| `V1.6.22` | 审单规则页权限码纠正、菜单归属、脏规则清理 |
| `V1.6.23` | 信用铺底 452 人 + 三个控制参数 |
| `V1.6.24` | 违规原因字典 + `op_quality.violation_reason_code` |
| `V1.6.25` | 预检漏拦看板菜单与授权 |
| `V1.6.26` | 表/列注释规范化 |
