## 为什么需要多种账号

本系统是审批驱动的业务流：**同一个人不能既是提单人又是审批人**（引擎有防自审判定）。想演示一条完整链路，至少需要下面这几类身份。请按角色而不是按人名理解它们。

| 角色类别 | 演示时要它做什么 | 需要的权限面 |
|---|---|---|
| 普通员工 / 提单人 | 提报销单、上传附件、查看自己的单据进度、撤回被驳回的单 | 仅 `expense`/`document` 自助面 |
| 部门审批人（上级） | 一级审批通过/驳回/加签/转办 | 审批待办面 |
| 财务初审 / 复核 | 共享作业池领取、审核、退回、批量审批 | `sharing` + `compliance` 作业面 |
| 出纳 | 付款批次生成与执行、银企对账 | `pay`/`bank`/`treasury` 付款面 |
| 总账会计 | 凭证复核与过账、月结检查 | `glex`/`gl` 凭证面 |
| 影像/档案岗 | 影像调阅、归档、借阅与销毁 | `image` + `compliance.archive` |
| 系统配置管理员 | 维护主数据、流程模型、权限、编号规则 | 租户管理面（权限点很多，注意大 token） |
| 平台运营账号 | 开通租户、套餐与功能开关 | `/api/platform/**`（**租户账号进不去这里**） |
| 跨公司对照账号 | 验证 A 公司看不到 B 公司单据 | 与上面某个角色同权限、不同归属主体 |

**最后一类经常被忽略但没有它就无法证明多租户隔离有效**，请务必准备。

2. **账号去实名**：用户名与显示名不得使用真实姓名、工号、手机号。本项目此前做过一轮去实名化处理（全部为别名、无重名），发布前请**重新验证**这条事实是否仍成立——它只在特定演练库上达成过。
3. **权限最小真实集**：演示角色不应带上生产专用的高危权限（例如直接改凭证、直接改预算占用数）。
