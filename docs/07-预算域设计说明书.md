# 07-预算域设计说明书（P5）

> 阶段：P5 预算域 
> 覆盖：预算基础主数据（期间/成本中心/城市/汇率/费用标准）+ 预算核心（方案/明细/占用/调整单）
> 位置：`com.fssc.budget` + `com.fssc.masterdata`（基础主数据）

---

## 1. 本阶段交付

### 1.1 预算基础主数据（薄 CRUD，复用 P4 模板）

| 主数据 | 表 | 要点 |
|---|---|---|
| 会计期间 | md_period | 公司级，OPEN/CLOSED，结账人/时间 |
| 成本中心 | md_cost_center | 公司级，可绑定部门，树形 |
| 城市 | md_city | 城市分级（A/B/C），是否境外（费用标准取数） |
| 汇率 | md_exchange_rate | 币种对，生效期，MANUAL/自动来源（**无 status 列**） |
| 费用标准 | md_expense_standard | 按费用项+城市等级+岗位层级，DAY 日标准，WARN/HARD（**无 status 列**） |

### 1.2 预算核心

| 表 | 说明 |
|---|---|
| bg_scheme | 预算方案：年度/维度(DEPT,ITEM)/控制策略(WARN/HARD)/结转 |
| bg_item | 预算明细：dimKey 维度键唯一；汇总值 total/adjust/occupy/used |
| bg_occupy | **占用流水（只增不改，无 del_flag）**：OCCUPY/RELEASE/WRITE_OFF |
| bg_adjust / bg_adjust_line | 预算调整单：ADD/CUT/TRANSFER，审批后并入预算 |

**占用模型**：`可用额度 = total_amount + adjust_amount - occupy_amount - used_amount`
**流水是账，汇总是视图**：bg_occupy 只增不改，bg_item 汇总在同一事务内同步。

接口：`/api/tenant/budget/scheme|item|occupy|adjust/**`；权限码 `budget:{域}:*`；写操作落审计。

## 2. 验证报告（全部实测通过，JDK 26 + MySQL 8）

| 用例 | 结果 |
|---|---|
| 预算基础主数据（期间/成本中心/城市/汇率/费用标准） |  全部可查 |
| 预算方案/明细 |  2026 年度方案（HARD）、3 条明细 |
| check 3 万（可用 100000） |  返回可用额 |
| occupy 占用 3 万 |  成功 |
| **再占 8 万（超预算）** |  **HARD 硬控拒绝（400 预算不足）** |
| release 释放 3 万 |  可用恢复 100000 |
| writeOff 核销 5 千 |  used +5000，**占用不产生负值**（受占用余额约束） |
| 调整单创建 + 审批（ADD 增拨 5 万） |  审批后可用 = 100000+50000-5000 = 145000 |
| 占用流水只增不改 |  bg_occupy 3 条（OCCUPY/RELEASE/WRITE_OFF），无 del_flag 无 delete |
| 全量冒烟回归 |  verify-demo.sh 全绿 |

## 3. 本轮抓到的坑

1. **md_exchange_rate / md_expense_standard 无 status 列**：生成器默认带 enable 方法（getStatus/setStatus）→ 编译失败。
   → 这两张表按"无状态"处理，移除 enable 方法/端点与 create 的 status 默认逻辑。
2. **自定义 @Insert 不经过 MetaObjectHandler**：bg_adjust_line 的 tenant_id 为 null → NOT NULL 报错。
   → 自定义 SQL 的实体必须显式 setTenantId（BgOccupy 从一开始就显式设置所以正常）。
3. **核销不能无条件减占用**：原实现 writeOff 直接 occupy -= amount，在"占用已释放后再核销"的合法场景
   会产生**负占用**（实测 -5000）。→ 核销占用转出量 = min(实际占用, 核销额)，绝不产生负值。
