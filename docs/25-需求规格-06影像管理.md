# 6. 影像管理设计方案

> 基于《财务共享项目详细业务设计方案_影像系统0425.docx》整理

---

## 6.1 整体业务流程

### 6.1.1 业务说明

业务人员在业务系统保存或提交单据之后，打印单据封面，并连同纸质单据及相关的附件提交至影像扫描岗，扫描岗签收单据及纸质附件进行扫描、上传（某些业务是先进行审批之后再扫描），扫描完毕后业务审批及财务审核，本地审核时若发现影像异常由扫描岗重新扫描或增补扫描，若影像正常，则流程流转到各业务系统，同时影像系统完成存储。

### 6.1.2 业务流程

| 序号 | 流程节点 | 流程说明 | 参与人 |
|-----|---------|---------|-------|
| 1 | 单据提交 | 业务人员在业务系统保存或提交单据，打印单据封面 | 业务人员 |
| 2 | 签收单据 | 扫描岗签收纸质单据及附件 | 扫描岗 |
| 3 | 扫描上传 | 扫描岗进行扫描、上传影像至影像系统 | 扫描岗 |
| 4 | 业务审批 | 业务审批流程进行审批 | 业务领导 |
| 5 | 财务审核 | 财务人员审核影像 | 财务人员 |
| 6 | 异常处理 | 若发现影像异常，扫描岗重新扫描或增补扫描 | 扫描岗 |
| 7 | 流程流转 | 影像正常则流程流转到各业务系统 | 系统 |

## 6.2 Web服务端-系统设置

### 6.2.1 业务说明

扫描需要系统配置一些扫描相关的设置信息，比如识别哪些单证类型、如何识别等。

### 6.2.2 功能说明

#### 业务类型设置

支持以下业务类型：
- **费用报销业务**
- **采购结算业务**
- **合同存档业务**
- **资料存档业务**

#### 文件种类识别设置（单证类型）

| 业务类型 | 封面类型 | 支持的单证类型 |
|---------|---------|---------------|
| 费用报销业务 | 费用报销单封面 | 增值税专用发票24×14mm、增值税普通发票24×14mm、增值税电子普通发票24×14mm、附件 |
| 采购结算业务 | 采购结算封面 | 增值税专用发票24×14mm、增值税普通发票24×14mm、增值税电子普通发票24×14mm、附件 |
| 合同存档业务 | 合同封面 | 附件 |
| 资料存档业务 | 资料封面 | 附件 |

#### 条码规则

- 所有业务类型的封面条码规则：**QRCode**
- 封面条码必须唯一，即使不同的ERP账套

#### 系统图片和数据配置

**1）费用报销业务**

| 配置项 | 说明 |
|-------|------|
| 系统图片 | 图片（报销单封面）、图片（增值税专用发票24×14mm）、图片（增值税普通发票24×14mm）、图片（增值税普通电子发票24×14mm）、图片（附件） |
| 系统图片数据 | 发票数据（增值税专用发票24×14mm、增值税普通发票24×14mm、增值税普通电子发票24×14mm） |

**2）采购结算业务**

| 配置项 | 说明 |
|-------|------|
| 系统图片 | 图片（采购结算封面）、图片（增值税专用发票24×14mm）、图片（增值税普通发票24×14mm）、图片（增值税普通电子发票24×14mm）、图片（附件） |
| 系统图片数据 | 发票数据（增值税专用发票24×14mm、增值税普通发票24×14mm、增值税普通电子发票24×14mm） |

**3）合同存档业务**

| 配置项 | 说明 |
|-------|------|
| 系统图片 | 图片（合同封面）、图片（附件） |
| 系统图片数据 | 无 |

**4）资料存档业务**

| 配置项 | 说明 |
|-------|------|
| 系统图片 | 图片（封面）、图片（附件） |
| 系统图片数据 | 无 |

**重要规则**：各种业务封面的规则设置不能重复。

## 6.3 Web服务端-影像任务

### 6.3.1 业务说明

扫描客户端提交上传后，服务器生成影像任务，然后接收数据和图片，把数据和图片存储在影像任务下面；通过查询每笔影像任务可以查看每笔业务单据的图片和发票数据。

### 6.3.2 功能说明

1. **影像任务创建**：影像任务根据每笔业务进行创建，创建依据是封面和封面下面的附单
2. **影像任务删除**：删除图片和数据
3. **影像任务查询**：支持默认查询和高级查询
4. **影像任务状态更新**

### 6.3.3 业务流程

| 序号 | 流程节点 | 流程说明 | 参与人 |
|-----|---------|---------|-------|
| 1 | 任务创建 | 扫描客户端上传后创建任务 | 扫描岗 |
| 2 | 任务查询 | 可以根据封面的条码号（业务编号）进行查询以及一些其他状态信息 | 扫描岗 |
| 3 | 任务删除 | 针对错误的任务进行删除 | 扫描岗 |
| 4 | 状态更新 | 更新任务状态和调阅审核状态 | 扫描岗 |

### 6.3.4 状态定义

**任务状态**：

| 状态 | 说明 |
|-----|------|
| 待采集 | 任务已创建，等待扫描采集 |
| 已采集 | 扫描采集完成 |
| 待重采 | 需要重新采集 |
| 待补采 | 需要补充采集 |
| 待作废 | 等待作废确认 |
| 已作废 | 已作废 |

**调阅审核状态**：

| 状态 | 说明 |
|-----|------|
| 空白 | 未进行调阅审核 |
| 审核中 | 正在审核 |
| 审核通过 | 审核通过 |
| 审核未通过 | 审核未通过 |

**封单状态**：

| 状态 | 说明 |
|-----|------|
| 已封单 | 单据已封存 |
| 未封单 | 单据未封存 |
| 已解单 | 单据已解封 |

## 6.4 Web服务端-影像调阅评价

### 6.4.1 业务说明

外部系统进行调阅影像，例如：费用报销单做审批流的时候，需要看影像，并且对影像进行相关的评价（整单作废、重新采集影像等）；有些是属于档案的角度去调阅，查看影像为了不用去查看实物档案。

### 6.4.2 功能说明

1. **影像调阅页面**：提供影像调阅的页面
2. **影像评价操作**：提供影像的评价操作
3. **调阅数据接口**：提供影像的调阅数据接口

### 6.4.3 业务流程

| 序号 | 流程节点 | 流程说明 | 参与人 |
|-----|---------|---------|-------|
| 1 | 影像数据 | 实物的影像、发票数据 | 调阅者 |
| 2 | 页面审核调阅 | 通过调阅URL访问页面 | 调阅者 |
| 3 | 影像呈现 | 页面呈现影像 | 调阅者 |
| 4 | 评价操作 | 整单重采集、整单作废、补采集 | 调阅者 |
| 5 | 调阅数据接口 | 提供多种查询方式获取影像数据 | 调阅系统 |

### 6.4.4 调阅数据接口

| 接口类型 | 输入参数 | 输出参数 |
|---------|---------|---------|
| 按业务单号范围查询 | 业务单号范围 | 业务任务信息 |
| 按业务单号查询 | 业务单号 | 业务任务字段 |
| 按业务单号查询发票 | 业务单号 | 此单下的发票数据 |
| 按记账年月和账套查询 | 记账年月、账套 | 影像页面 |

## 6.5 Web服务端-评价处理

### 6.5.1 业务说明

外部系统进行调阅影像评价后，对影像做出了一些要求处理：整单重采集、补采集、整单作废等。

### 6.5.2 处理规则

| 评价类型 | 处理方式 | 操作说明 |
|---------|---------|---------|
| 补采集 | 扫描补采 | 扫描人员需要将封面和需要补采的影像一起扫描，原已有影像不需要再次扫描 |
| 整单重采集 | 重新扫描 | 扫描人员需要将原单据所有纸质文件重新扫描 |
| 整单作废 | 删除/放行 | 扫描人员可以选择"删除单据"；若确认单据无误，可点击"人工放行"恢复为正常单据 |
| 数据不完整 | 编辑补全 | 在图文模式下点击"编辑"补全缺失内容，然后点击"人工放行"手动恢复为正常单据 |

## 6.6 Web服务端-异常处理

### 6.6.1 业务说明

针对扫描后上传到服务端后，发票有重复的异常影像，系统进行人工处理。

### 6.6.2 异常类型与处理规则

| 异常类型 | 说明 | 处理方式 |
|---------|------|---------|
| 单据重复 | 同一单据被重复扫描 | 核对后若确实重复，执行"删除"操作 |
| 不同单据发票重复 | 不同单据间发票重复 | 修改发票信息或删除重复发票，然后点击"异常检查" |
| 单据法人税号与发票税号不一致 | 单据与发票税号不匹配 | 核对后若确实不匹配，"删除"单据，重新扫描 |
| 发票数据识别不完整或缺失 | 发票信息识别不全 | 在"详情-图文模式"找到相应发票，通过"编辑"完善发票信息，然后点击"异常检查" |
| 发票验真失败 | 发票验证不通过 | 在"详情-图文模式"找到相应发票，完善信息后可直接"平台验真"或"人工处理"，然后点击"异常检查" |
| 单据内发票重复 | 同一单据内发票重复 | 在"详情-图文模式"找到相应发票，删除重复发票，然后点击"异常检查" |

### 6.6.3 异常处理流程

1. 扫描后上传到服务端
2. 系统自动识别异常
3. 人工查看异常详情
4. 根据异常类型选择处理方式
5. 点击"异常检查"按钮验证是否恢复正常
