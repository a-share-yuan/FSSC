## 2. 真实登录（双通道）

```
POST /api/auth/login
{ username, password, subjectType, tenantCode? }

PLATFORM → pf_user 查用户 + BCrypt → is_super=1 得 *:*:*，否则按角色取权限码
TENANT   → tenantCode 查 pf_tenant（识别企业）→ TenantContext.callAs(tenantId)
           校验 sys_user + BCrypt → 装载 perms/features/dataScope 进 Token
```

安全要点：
- 租户识别用 **tenantCode（企业编码）**，登录请求体没有 tenantId —— 无法指定冒充他人租户；
  最终以"能否通过该租户 sys_user 的 BCrypt 校验"为准。
- 权限装载在 `TenantContext.callAs(tenantId)` 内执行，租户拦截器自动为
  `sys_user/sys_role/sys_user_role/sys_role_menu` 追加 `tenant_id`，SQL 零手写。
- 权限码 = 角色→菜单 perms；功能码 = 套餐功能（pf_tenant_package ∩ pf_package_feature）；
  数据范围 = min(data_scope)，无角色默认 5（本人）。租户管理员（is_admin=1）直接 `*:*:*`。
- 登录日志双轨：平台 pf_login_log（status 1成功/0失败），租户 sys_login_log（status 0成功/1失败）。

## 3. 租户生命周期（状态机 + 实时拦截）

```
APPLYING 待审核 → NORMAL 正常 → FROZEN 冻结 → CANCELLED 已注销
APPLYING → REJECTED 已拒绝
FROZEN   → NORMAL 解冻
NORMAL   → CANCELLED 注销（直接注销，简化）
```

两道拦截：
1. **请求入口**：`TenantFilter` → `PfTenantStatusValidator`（每请求查 pf_tenant，
   冻结/注销/过期 → 403 拦截；已签发 Token 也立即失效）。
2. **登录入口**：`AuthService.checkTenantStatus`（先拦一步，避免无效认证请求）。

## 4. 双轨审计（@OperLog）

- 平台操作 → `pf_oper_log`（无 tenant_id）；租户操作 → `sys_oper_log`（带 tenant_id）。
- 记录：操作人/模块/类型/描述/方法/URI/参数（password/token 脱敏）/结果/耗时/成败。
- 审计表**无 del_flag**，Mapper 只提供 insert —— 不可删除（架构铁律）。

## 6. 本轮抓到的坑

1. **MyBatis type-aliases 简单名冲突**：demo 域与 system 域都有 `SysUser` 实体，
   `type-aliases-package: com.fssc` 按简单名注册别名 → 启动报
   `The alias 'SysUser' is already mapped`。→ 删除 demo 重复实体统一用 system 版；
   移除 type-aliases-package 配置（用全限定名）。
2. **sys_login_log 列名与 pf_login_log 不同**：租户表是 `user_name`/`ipaddr`，
   平台表是 `username`/`login_ip`。实体字段必须 @TableField 对齐，不能想当然复用。
3. **平台操作日志与租户操作日志 status 语义相反**：pf_oper_log/pf_login_log 用
   1成功/0失败，sys_oper_log/sys_login_log 用 0成功/1失败（建表约定如此，需对照 SQL 核对）。
