## 二、P1-8 消除 Mock 残留（本轮重点）

### 2.1 凭证推送：内存 Map + 假延迟 → 可插拔通道 + 落库

**整改前**（`VoucherPushService`）：
- 推送记录存 `ConcurrentHashMap` → 多实例不一致、重启即丢、无审计；
- 含 `Thread.sleep(150)` 人为网络延迟；
- 推送目标硬编码规则，无真实对接路径。

**整改后**：
- 新增通道 SPI `VoucherPushChannel`（`LocalVoucherPushChannel` 默认 / `HttpVoucherPushChannel` 真实 HTTP）；
- 运行时路由 `VoucherPushChannelRouter`：`sys_config voucher.push.channel` → 回退 yml `fssc.voucher.push.channel`（默认 `local`）；未知值安全回退；
- 推送记录落库新表 **`op_voucher_push_log`**（多租户，tenant_id 自动填充）；
- 报文含凭证头 + 分录明细，供 NC/IFS 建账；
- 失败语义：不抛穿，以 `status=FAILED + error` 返回并落库。

**验证**：
```
POST /api/tenant/voucher/push/35
→ {"status":"SUCCESS","channel":"local","externalNo":"NC_SYSTEM-JZ2026090900001-20260910210114"}

切换 voucher.push.channel=http（未配 url）
→ {"pushed":false,"status":"FAILED","error":"未配置推送接口地址（sys_config voucher.push.url）"}   ← 优雅降级，HTTP 200 + body.code=0
```
落库校验：`op_voucher_push_log` 中 `tenant_id=1` 自动填充，`channel/status/external_no/request_body` 均正确。

### 2.2 薪酬核算：写死人均常量 → 租户可配置标准

**整改前**（`GlSalaryRunService.calculateRun`）：人均工资 8000/扣除 200/社保 1000/个税 300 写死在代码里，注释自承"模拟人均数据（演示用）"。
**整改后**：四项标准改为 `sys_config` 参数（`salary.std.basic|deduction|social|tax`），未配置回退内置默认；非法值/负值安全回退。

**验证**：把 `salary.std.basic` 改为 9000，按 10 人核算 → `salaryAmount=90000.0`，`total=75000.0`（=90000−2000−10000−3000，与 `assertSalaryFormula` 强校验一致）。验证后已改回 8000，测试批次与流程实例已清理。
