## ⓪ 生效性前提：node_key 能否对上已部署 BPMN

 共 **262 行**（另 0 行所属模型未部署）的 `node_key` 在其模型的**已部署** BPMN 里找不到对应 userTask。`WfNodeConfigResolver.resolve` 是精确键匹配（V1.3.24 已移除按序号兜底），因此这些行配的超时 **和** 升级层级 **和** 空策略**一律不会被读取**——无论配成哪一档。

成因：已部署 BPMN 的 userTask id **非连续**（如 TRAVEL 只有 `2/3/4/6/7/8`，没有 `Task_1`/`Task_5`——那两个位置是"提交步骤"与"金额分档网关"），而配置表按**设计位置**连续编号 `Task_1..N` ⇒ 位置落在非 userTask 节点的行整体成为孤儿。
