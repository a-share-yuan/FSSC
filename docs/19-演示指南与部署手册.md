## 一、演示地址

| 入口 | 地址 | 说明 |
|---|---|---|
| **PC 端（推荐演示）** | http://localhost:8080 | 前端入口（`vite dev` 与 `vite preview` **同端口 8080**），已代理 `/api` → 后端 8089 |
| **H5 移动端工作台** | http://localhost:8080/#/h5 | 独立移动端页面（我的单据 / 发起报销 / 待审批） |
| **大屏看板** | http://localhost:8080/#/dashboard | 全屏报表看板（支持进入大屏模式） |
| 后端 API | http://127.0.0.1:8089/api | OpenAPI 文档 `/doc.html` |
| **健康探活（免鉴权）** | http://127.0.0.1:8089/api/health | 回显 DB/Redis 组件状态、版本、运行时长；探针与巡检脚本使用 |
| 健康探活（Actuator） | http://127.0.0.1:8089/actuator/health | 另含 `/actuator/health/liveness`、`/actuator/health/readiness` |

> 代理目标默认 `127.0.0.1:8089`，可用环境变量 `FSSC_API_TARGET` 覆盖（如指向远端后端）。
> 演示地址为本地预览；如需公网演示，将前端构建产物部署到 Nginx，后端 8089 反向代理（见第四节）。

## 三、人工测试流程（端到端用例）

> 以下流程均已在本地实测通过；标注 **【预期】** 的为验证点。
> 演示路径基于 PC 端左侧动态菜单（菜单按登录账号权限自动裁剪）。

### 场景 A：报销主线（推荐首演）

| 步骤 | 操作 | 预期 |
|---|---|---|
| 1 | 打开 http://localhost:8080 ，用 `admin` / `123456`（租户 DEMO1）登录 | 进入报表看板，左侧菜单完整 |
| 2 | 进入「费用报销」→ 填写标题/申请日期 → 加费用明细（费用项选差旅费，金额 300） | 明细行可增删 |
| 3 | 点「选择发票文件」上传图片/PDF（真实上传到 sys_file） | 提示"附件已上传"，显示文件名 |
| 4 | 点「保存草稿」 | 我的单据出现草稿，单号形如 `BX20260811xxxx`（编号规则生成） |
| 5 | 点「提交审批」 | 状态变 SUBMITTED/APPROVING，生成待办 |
| 6 | 进入「审批工作台」→ 点「同意」 | 单号状态 APPROVED，自动派工入池 |
| 7 | 报表看板查看趋势 | 月度趋势出现该笔金额 |

### 场景 B：事前申请 → 转报销单（闭环）

| 步骤 | 操作 | 预期 |
|---|---|---|
| 1 | 左侧「事前申请」→ 新建 APPLY 单（金额 800）→ 提交 → 审批工作台同意 | 状态 APPROVED |
| 2 | 「事前申请」列表点「转报销单」 | 生成新 CLAIM 草稿（金额/明细复制），弹提示 |
| 3 | 重复点「转报销单」 | 被拒绝"该事前申请已转报销单" |
| 4 | 数据库 `exp_bill_relation` 查关联 | 存在 APPLY_CLAIM 记录，use_amount=800 |

### 场景 C：借款 → 还款闭环

| 步骤 | 操作 | 预期 |
|---|---|---|
| 1 | 「借款管理」→ 新建 LOAN 单（2000）→ 提交 → 审批同意 | 状态 APPROVED，借款人借款余额=2000 |
| 2 | 「借款管理」新建 REPAY 还款单（800）→ 提交 → 审批同意 | 状态 APPROVED |

## 四、部署手册

### 1. 环境要求

| 组件 | 版本 | 说明 |
|---|---|---|
| JDK | 21+（开发机 26 实测可用） | 生产建议 21 |
| Maven | 3.9+ | 本机用 `python scripts/mvn.py <args>` 封装（classworlds + Windows 路径） |
| MySQL | 8.0 | utf8mb4；Connector/J 9.x 需 `connectionCollation=utf8mb4_general_ci` |
| Node.js | 20+（构建用） | 构建产物托管在 Nginx 即可，运行期不需要 Node |

### 2. 数据库初始化

```bash
cd fssc

# ① 建库建表（顺序加载 db/00-schema.sql ~ 08-sharing.sql；Flowable ACT_/FLW_ 表由引擎首启自动创建）
bash scripts/db-init.sh            # 默认 127.0.0.1:3306 root/123456

# ② 种子数据（幂等可重跑，顺序执行）
mysql --default-character-set=utf8mb4 -uroot -p123456 fssc < scripts/seed-p2.sql   # 平台+租户+RBAC+账号
mysql --default-character-set=utf8mb4 -uroot -p123456 fssc < scripts/seed-p3.sql   # 租户系统域菜单/组织/字典
mysql --default-character-set=utf8mb4 -uroot -p123456 fssc < scripts/seed-p4.sql   # 主数据（币种/科目/费用项/供应商…）
mysql --default-character-set=utf8mb4 -uroot -p123456 fssc < scripts/seed-p5.sql   # 预算+会计期间
mysql --default-character-set=utf8mb4 -uroot -p123456 fssc < scripts/seed-p18.sql  # P18 增量：新功能菜单+编号规则
```

> 数据连接配置：`fssc-server/fssc-start/src/main/resources/application-dev.yml`（默认 `127.0.0.1:3306/fssc, root/123456`）。

### 3. 后端部署

```bash
cd fssc/fssc-server

# 构建（含单测；跳过测试加 -DskipTests）
python ../scripts/mvn.py clean package
# 产物：fssc-start/target/fssc-server.jar

# 启动（默认端口 8089，脚本内置 120 秒 LISTENING 等待，便于与前端联动启动）
cd ../.. && bash scripts/run-server.sh --port 8089

# 验证（探活 + 登录，二选一即可判断服务是否就绪）
curl http://127.0.0.1:8089/api/health
# 返回 {"code":0,"data":{"status":"UP",...}} 即成功

curl -X POST http://127.0.0.1:8089/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username":"admin","password":"123456","subjectType":"TENANT","tenantCode":"DEMO1"}'
# 返回 {"code":0,"data":{"token":"..."}} 即成功
```

**生产部署要点**：
- 建议 JDK 21（更高版本需 `--add-opens` 参数，见 run-server.sh 说明）
- 端口：默认 **8089**，可 `--port <port>` 覆盖（**不要**用 8080，已被前端占用）
- 应用配置：数据库连接、OCR/银企切换均在 `application-dev.yml`（`fssc.ocr.provider` / `fssc.bank.gateway`）
- **生产必须注入 `FSSC_JWT_SECRET`（≥32 字节强随机）与 `FSSC_DB_PASSWORD`**：非 dev profile 且沿用默认密钥时启动自检会 fail-fast 拒绝启动
- 运维监控配置见 `docs/36-上线运维手册（可观测性与变更安全）.md`

### 4. 前端部署

```bash
cd fssc/fssc-web

# 安装依赖
npm install

# 开发模式（代理 /api → 127.0.0.1:8089）
npm run dev          # http://localhost:8080（与 preview 同端口，勿同时启动）

# 生产构建
npm run build        # 产物 dist32/（outDir 轮换，见 vite.config.js；构建前先 unset NODE_OPTIONS）

# 本地预览构建产物（代理 /api → 127.0.0.1:8089）
npm run preview      # http://localhost:8080
```

**Nginx 托管示例**（生产）：

```nginx
server {
    listen 80;
    server_name fssc.example.com;

    root /data/fssc-web/dist;
    index index.html;

    # 前端路由（hash 路由，history fallback 可选）
    location / {
        try_files $uri $uri/ /index.html;
    }

    # 后端反向代理
    location /api/ {
        proxy_pass http://127.0.0.1:8089;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        client_max_body_size 50m;   # 附件上传
    }
}
```

### 5. 第三方对接（可选，需外部凭据）

| 能力 | 架构 | 切换方式 | 前提 |
|---|---|---|---|
| 真实 OCR（发票识别） | `OcrProvider` 接口，Mock @Primary | 配置 `fssc.ocr.provider: tencent` | 腾讯云 SecretId/SecretKey |
| 银企直联 | `BankGateway` 接口（Default 模拟） | 配置 `fssc.bank.gateway: http` | 银行网关地址与密钥 |

> 未配置前使用 Mock 实现，全流程可跑通不依赖外部服务。

### 6. 冒烟回归

```bash
# 一键回归（20+ 用例：登录/租户/主数据/报销/审批/预算/付款/权限/隔离）
bash scripts/verify-demo.sh
# 输出「 全部冒烟用例通过」即健康
```
