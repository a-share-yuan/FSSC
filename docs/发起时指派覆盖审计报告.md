## ROLE 行：配置值与 BPMN 候选组的关系

ROLE 配置同样先被 `applyNodeConfig` 落成"角色首个持有人"，随后可能被候选组解析覆盖；**只有二者不一致时结果才会变**，所以这一维度决定了上面那个缺陷的真实暴露面。

| 口径 | 行数 |
|---|---:|
| 配置值 == 候选组：覆盖后同结果（无感） | 300 |
| 孤儿行：node_key 不在已部署 BPMN | 212 |
| POOL 任务池：两处都跳过自动指派 | 48 |
| 多实例节点：applyNodeConfig 已提前 return | 3 |
| **合计** | 563 |

>  该维度**零行**：全部 ROLE 行的配置值与 BPMN 候选组一致（或落在孤儿/POOL/多实例分支），即"发起时指派覆盖"缺陷当前**零线上影响**——属**潜在**缺陷：一旦有人在 BPMN 带候选组的节点上把 assign_type 改成 USER/INITIATOR 或改角色，就会静默指错人。

> 另有 **212 行 ROLE** 是孤儿行（分布前 10）：GL_MONTH_CLOSE×12，GL_MERGE×7，FM_ARCHIVE×6，FM_BORROW×6，GL_SALARY_PAY×6，INV_INTERNAL_SALE×6，PAY_PLAN_PLATE×6，FA_TRANSFER_CROSS×5，INV_ISSUE_NONPROJECT×5，INVOICE_MATCH×5
