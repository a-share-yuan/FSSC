<h2 id="1">1. 整体系统功能框架</h2>

**系统概述**：财务共享平台是一套覆盖费用报销、合同管理、影像管理、发票管理、共享运营、预算管理、移动端处理及管理报表的综合财务系统。系统采用B/S架构，支持多组织、多币种、多预算体系，与外部系统（HR系统、商旅平台、NC/IFS财务系统、BPM系统、银企系统）深度集成。

**核心集成关系**：

- HR系统：员工信息同步、考勤数据推送
- 商旅平台：机票/酒店预订信息同步
- NC/IFS：预算科目、成本中心、预算数据、记账凭证
- BPM系统：流程审批待办推送
- 银企系统：支付处理

### 3.10 关联单据的预算控制流程

**业务说明**：费用单据在提交时触发预算检查，预算是占用、释放、扣减的完整流程。

**业务流程**：

1. 单据提交 → 预算检查 → 预算充足则占用预算
2. 预算不足时：柔性控制（允许提交但预警）/ 刚性控制（不允许提交）
3. 单据关闭/作废 → 释放预算
4. 报销完成 → 实际扣减预算

#### 4.3.4 机票结算申请

**业务说明**：行政人员统一报销机票费用，需关联事前申请单，根据实际行程及发票金额填写报销单。记账后可根据报销与申请的差额更新预算。

<h2 id="5">5. 合同管理设计方案</h2>

### 5.1 合同类型

**业务说明**：定义合同的分类类型，用于区分不同业务场景下的合同，包括PO合同（采购订单）和非PO合同（费用类合同）。

**功能说明**：

- 新增合同类型：编码、名称、状态
- PO合同由IFS系统录入并同步
- 非PO（费用类）合同在共享平台手工录入

### 5.2 合同新增和审批

#### 5.2.1 业务场景

适用于需要在共享平台系统中进行支付的非PO（费用类）合同关键信息的录入和审批，并对支付记录进行统计管理。

**合同分类体系**：

- **PO合同**：资产类、成本类、外包类等，由IFS系统录入，自动同步到合同台账
- **非PO合同**：费用类合同，在共享平台手工录入
- **区分字段**：系统增加PO和非PO区分字段

#### 5.2.2 业务流程

| 序号 | 流程节点     | 流程说明                                        | 参与人    |
| -- | -------- | ------------------------------------------- | ------ |
| 1  | 合同录入     | 操作人系统中填制单据，录入相应字段                           | 经办人    |
| 2  | 保存提交审批   | 提交时系统进行单据业务规则校验                             | 经办人    |
| 3  | 合同审批     | 各级业务领导进行工作流审批，审批不通过的单据将会打回经办人处修改，修改完毕后再进行提交 | 业务领导   |
| 4  | 合同台账     | 来源有两类，一类是在共享系统手工录入的合同，一类由IFS同步              | 经办人/接口 |
| 5  | 编制单据引用合同 | 经办人可新增申请、报销、付款等单据时引用合同                      | 经办人    |
| 6  | 更新付款信息   | 业务单据记账完成之后更新该合同的实际付款记录                      | 系统     |

**审批流程规则**：

1. 将合同审批流程纳入合同台账，统一从系统审批，杜绝非PO合同纸质审批的情况发生
2. 按照"谁执行谁审批入谁的成本"的原则进行核算
3. 考虑短期（3个月）内合计订单金额达到审批权限标准的按照最高审批权限进行审批，规避人为及非人为拆单的可能

#### 5.2.3 功能说明

1. **合同录入**：录入非PO（费用类）合同关键信息，纸质原始合同文件可通过附件添加或扫描在系统中供查阅
2. **招标比价信息**：新增是否招标比价、中标原因、是否同比价格递减、是否预算内、是否达成效果等必填字段
3. **PO合同同步**：PO（资产、成本、外包等）合同由IFS系统录入，自动同步到合同台账中
4. **预算控制**：
   - 固定金额合同通过合同总额冻结预算
   - 无固定金额（长期协议、以量定额）合同不控制预算
5. **审批生效**：
   - 审批后的合同可进行附件补录
   - 审批完成已生效状态的合同才可被报销单、付款单等业务单据引用
6. **付款控制**：
   - 系统不允许超合同金额付款，如果超合同金额付款业务使用合同调整
   - 合同在有效期内可被对公报销单和对公付款单引用
   - 合同可以手工关闭，已关闭合同不能被引用
7. **支付记录管理**：
   - 支付记录在对公报销单、对公付款单引用合同后自动更新
   - 线下支付可手工添加支付记录
8. **合同变更**：
   - 合同金额、签订双方、有效期等情况发生改变后可以通过合同变更对原合同进行变更
   - 新合同生效后原合同自动关闭
   - 变更后会有原合同和新合同，可以进行关联查询
9. **补充协议**：
   - 原合同新签补充协议可以通过补充协议录入
   - 会关联原合同和补充协议
   - 原合同和补充协议可以分别执行
10. **数据导入导出**：支持历史合同导入，导出合同模板，导入合同信息

<h2 id="6">6. 影像管理设计方案</h2>

### 6.1 整体业务流程

**业务说明**：业务人员在业务系统保存或提交单据之后，打印单据封面，并连同纸质单据及相关的附件提交至影像扫描岗，扫描岗签收单据及纸质附件进行扫描、上传（某些业务是先进行审批之后再扫描），扫描完毕后业务审批及财务审核，本地审核时若发现影像异常由扫描岗重新扫描或增补扫描，若影像正常，则流程流转到各业务系统，同时影像系统完成存储。

**业务流程**：

| 序号 | 流程节点 | 流程说明                    | 参与人  |
| -- | ---- | ----------------------- | ---- |
| 1  | 单据提交 | 业务人员在业务系统保存或提交单据，打印单据封面 | 业务人员 |
| 2  | 签收单据 | 扫描岗签收纸质单据及附件            | 扫描岗  |
| 3  | 扫描上传 | 扫描岗进行扫描、上传影像至影像系统       | 扫描岗  |
| 4  | 业务审批 | 业务审批流程进行审批              | 业务领导 |
| 5  | 财务审核 | 财务人员审核影像                | 财务人员 |
| 6  | 异常处理 | 若发现影像异常，扫描岗重新扫描或增补扫描    | 扫描岗  |
| 7  | 流程流转 | 影像正常则流程流转到各业务系统         | 系统   |

<h2 id="12">12. 系统级可靠性增强（P0）</h2>

> 上线前必做项。详见 `32-需求规格-12系统级可靠性增强.md`。  
> 解决财务长链路（单据→审批→凭证→付款→核销）的一致性与合规性风险。

### 12.1 长链路一致性对账

#### 对账任务

- 定时（每日 + 手动触发）核对单据主表、凭证、付款记录三方金额一致性
- 规则：单据总额 = 凭证借贷方合计 = 已付金额 + 未付金额
- 不一致记录进入对账异常清单，支持人工处理与状态跟踪
- 支持按租户、单据类型、时间范围查询核对结果

### 12.2 金额防篡改

#### 提交校验和

- 单据提交时对关键字段（金额、收款账户、收款人）生成校验和（SHA-256）
- 审批/执行环节校验校验和，发现被篡改则拦截并提示
- 展示字段变更前后对照，辅助审计

### 12.3 审计留痕闭环

#### 关键变更审计

- 凭证修改、付款账户变更、审批意见、预算调整等关键变更记录 before/after JSON
- 只追加不更新（审计流水表无 del_flag，Mapper 不提供 delete）
- 支持按单据/单据类型导出审计轨迹

#### 审计导出

- 单张单据维度导出完整生命周期（创建→提交→审批→凭证→付款）
- 支持租户运营管理员查看

### 12.4 幂等与并发控制（P1）

#### 预算占用并发锁

- 预算占用/核销/扣减必须防止并发超占：预算科目行级锁（SELECT ... FOR UPDATE）串行化同一科目并发操作
- 占用流水只增不改（已实现），配合行锁保证"可用 = 总额 + 调整 - 占用 - 扣减"恒等

#### 付款幂等

- 付款批次（op_pay_batch）与付款记录（exp_bill_payment）加唯一业务键防重提/重复付款
- 付款执行幂等：同批次同明细不可重复执行；失败重试不产生重复付款记录

### 12.5 Flowable 历史数据归档（P1）

#### 归档清理任务

- ACT_HI\_* 流程引擎历史表只增不删，需配置化定期归档清理
- 保留策略：运行完成 N 个月后的历史数据清理（可配置保留月数）
- 业务侧 wf_instance/wf_task_history 保留（单据追溯用），引擎历史表按策略清理

### 12.6 主数据缓存分层（P1）

#### 缓存策略

- 高频读低频写的主数据（公司/科目/费用类型/字典/汇率）加缓存，降低 DB 压力
- 变更（增删改）时主动失效对应缓存
- 兜底：缓存失效/未命中回源 DB，缓存服务不可用不影响业务（fail-open 仅缓存层）

### 12.7 银企直连对账（P2）

#### 银行流水勾对

- 银行流水（sharing/statement）与付款记录（exp_bill_payment）自动勾对
- 未勾对流水/付款进入待核清单人工处理；支持按日期范围、状态查询

#### 数电票预留

- 发票管理预留数电票（全电发票）接口对接位，与 OCR/验真通道并列

### 12.8 月末关账控制（P2）

### 12.11 大表按月分区（阶段一容量优化）

#### 分区策略

- 流水/日志/历史类只追加表按月 RANGE COLUMNS(时间列) 分区：sys_oper_log、pf_oper_log、wf_task_history（oper_time）、bg_occupy、bank_reconcile（create_time）
- 预建 24 个月分区 + pMAX 兜底；新月份 ADD PARTITION，超期 DROP PARTITION 秒删
- 业务核心表（exp_bill/op_voucher 等，单列自增主键 + 按 id 高频更新）**不分区**，走结单归档策略
- 工具：scripts/gen_partition_p61.py 自动生成分区 DDL（SHOW CREATE TABLE → 主键加分区列 → 追加分区子句）

### 12.12 前端公共组件（上传 / 影像查看）

#### UploadButton 通用上传按钮

- el-upload + http-request 标准链路（走 axios 带 token），修复原生 input.click 在预览环境被浏览器拦截的问题
- 支持 mode=file（/system/file/upload）/ mode=image（/image/batch/upload-multi）；zone 存储区域参数；@done 回传文件记录
- 接入：文件管理、影像批次上传、费用报销发票附件（zone=TEMP）

#### FileViewer 通用影像/附件查看器

- 按文件类型分类预览：图片（9 种）el-image 内嵌+全屏 / PDF iframe / 其他类型新窗口打开兜底
- 接入六处：文件管理、影像任务、影像批次、共享工单处理、单据附件、发票影像、档案归档
