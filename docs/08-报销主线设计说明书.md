# 08-报销主线设计说明书（P6 · 一期核心）

> 阶段：P6 报销主线 （一期核心闭环）
> 覆盖：exp_bill 五类单据 + 校验链 + 预算联动 + Flowable 7 流程门面 + 审批/驳回/撤回
> 位置：`com.fssc.expense` + `com.fssc.workflow`

---

## 1. 本阶段交付

### 1.1 报销单据域 `com.fssc.expense`

| 表 | 说明 |
|---|---|
| exp_bill | 五类共用主表（APPLY/CLAIM/LOAN/REPAY/PAY，ADR-6），状态机 |
| exp_bill_line | 明细：费用项/科目/预算项/税额/标准校验标记（over_std） |
| exp_bill_attach | 附件：发票/影像，关联 bill 或 line |

接口 `/api/tenant/expense/bill/**`：saveDraft / submit / withdraw / void / detail / myPage。
权限码 `exp:bill:save|submit|withdraw|list`，写操作落审计。

**状态机**：`DRAFT → SUBMITTED/APPROVING → APPROVED / REJECTED / WITHDRAWN`；`DRAFT → VOID`。

### 1.2 Flowable 7 流程门面 `com.fssc.workflow`

- `WfEngineFacade`：**业务禁止直调 Flowable API**，统一走门面（部署/发起/审批/撤回/待办）。
- 流程定义 `expenseClaim`（资源目录自动部署）：开始 → 部门经理审批 → 通过/驳回双结束节点。
- `PROCESS_COMPLETED` 事件 → 发布 `WfProcessEndedEvent`（bizType/bizId/approved/comment）→
  报销域监听收尾（核销/释放/状态回写）。
- 接口 `/api/tenant/wf/todo|approve`。

### 1.3 提交链路（一期闭环）

```
saveDraft(草稿)
  → submit
    ① 校验链：费用项存在且启用 / 金额>0 / needInvoice 费用项必须有发票附件
    ② 预算占用：逐行 budgetItemId → budgetService.occupy（HARD 硬控超预算拒绝）
    ③ 发起 Flowable 流程（approver 默认本租户管理员）→ APPROVING
  → approve(true)  → 单据 APPROVED + 逐行核销（占用转已用）
  → approve(false) → 单据 REJECTED + 释放占用
  → withdraw       → 单据 WITHDRAWN + 释放占用
```

## 3. 本轮抓到的坑

1. **Flowable 7 事件 API 迁移**：`FlowableEvent/FlowableEntityEvent/FlowableEngineEventType/FlowableEventListener`
   从 `org.flowable.engine.delegate.event` 移到 `org.flowable.common.engine.api.delegate.event`，
   且 `FlowableEventListener` 新增 `getOnTransaction()` 抽象方法 → 继承 `AbstractFlowableEventListener` 并实现 `isFailOnException()`。
2. **Map.of 遇 null 抛 NPE**：待办接口用 `Map.of("title", vars.get("title"))`，流程变量缺失时 NPE → 改 HashMap 保护。
3. **种子重跑致费用项 id 漂移**：seed-p4 重跑后 md_expense_item auto_increment 未重置，
   差旅费 id 从 1 变 5，而 bg_item.item_id 仍引用 1 → "费用项不存在" → 需同步修正引用（数据一致性演练场）。
