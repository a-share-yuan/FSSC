## 2. 权限模型落地（P3 实测链路）

```
登录(BCrypt) → Token(perms/features/dataScope)
  → 菜单树：角色关联菜单(sys_role_menu，租户内) ∩ 套餐功能(feature_code 过滤)
  → 接口：@RequiresPerm 校验 perms（管理员 *:*:* 通配）
```

实测证据（见 §4）：alice（管理员）菜单树含 费用报销/事前申请/影像/系统设置，
**借款管理（F_LOAN）与预算管理（F_BUDGET）因标准版套餐未开通被自动剔除**；
普通用户 dave 只授权了 费用报销+发起报销 → 登录后菜单树精确等于这两个菜单。

## 3. 关键设计

- **菜单树不设权限**：`/menu/tree` 任何已登录租户用户可调（动态路由基础），
  内容已按 角色∩功能 裁剪，越权内容不会出现在树里。
- **关联表无 del_flag**：sys_role_menu / sys_user_role 用**物理删除**，
  不继承 BaseEntity（其 @TableLogic 会把 delete 变成 del_flag=1 逻辑删 → 列不存在报错）。
- **tenant_id 双保险**：关联表实体字段标 `@TableField(fill=INSERT)` 触发 MetaObjectHandler，
  业务代码再显式 setTenantId(TenantContext.getTenantId())。
- **开通闭环**：approve 时在 `TenantContext.callAs(tenantId)` 内创建 `admin_{code}` 管理员
  （BCrypt Admin@123，is_admin=1，登录即 *:*:*）。

## 5. 本轮抓到的坑（真实环境复现，已修）

1. **关联表无 del_flag → @TableLogic 逻辑删崩溃**：`sys_role_menu`/`sys_user_role` 无 del_flag 列，
   继承 BaseEntity 后 delete 变 `UPDATE ... SET del_flag=1 WHERE del_flag=0` → `Unknown column 'del_flag'`。
   → 关联表改为独立实体（物理删除），不继承 BaseEntity。
2. **MP 只在实体含 @TableField(fill) 字段时才调用 MetaObjectHandler.insertFill**：
   （加日志实测 insertFill 从未被调用）→ 关联表 tenantId 标 fill=INSERT 触发 + 业务显式 setTenantId 双保险。
3. **sys_oper_log 列名与 pf_oper_log 差异大**：租户表用 title/business_type/oper_url/oper_param/
   json_result/cost_time（非 module/oper_type/request_uri/request_param/response_data/cost_ms），
   实体与 Mapper 必须逐一对齐。
