# 部署运维

## 1. 三种部署形态

### 形态 A：jar 直跑（开发/小规模）
```bash
cd fssc/fssc-server && mvn -q clean package -DskipTests
java -jar fssc-start/target/fssc-server.jar
```
前置：MySQL 8（fssc + fssc_image 两库）+ Node 24（前端另起）。

### 形态 B：Docker Compose 单机全栈（评估/演示推荐）
```bash
cd fssc/docker && cp .env.example .env      # 填 FSSC_DB_PASSWORD / FSSC_JWT_SECRET
cd ../fssc-server && mvn -q clean package -DskipTests   # 产出 fssc-start/target/fssc-server.jar
cd ../docker && docker compose up -d --build            # MySQL(自动导入整库 dump) + 后端 + 前端
```
浏览器 `http://localhost:8080`（演示租户 `DEMO1`，`admin` 或 `100001`，口令 `123456`）。
首轮 `up` 会等 MySQL 把 `db/Dump<日期>/` 导完（实测 `fssc` 317 张表 + `fssc_image` 6 张表，约 3~10 分钟）；
backend 挂在 db 的健康检查上，导完才启动，不需要手工等。换演示数据版本只改 `.env` 里的 `FSSC_DUMP_DIR`。
`docker compose down` 保留数据；加 `-v` 连库与附件一起清掉，下次 up 重新导入 dump。

编排文件在 `fssc/docker/docker-compose.yml`；前端镜像 `docker/Dockerfile-web`（Node 24 构建 → nginx），
`/api` 反代由 `docker/nginx-web.conf` 承担。

只想起后端一个容器（库和前端自己跑）：
```bash
docker build -t fssc-server:1.0.0 -f docker/Dockerfile fssc    # 上下文必须是 fssc/
```
> `docker/Dockerfile` 是**单阶段**镜像，只 COPY 已打好的 fat jar ⇒ 必须先 `mvn package`；
> 它不吃源码，构建机上不需要 Maven。

### 形态 C：Kubernetes（生产）
`fssc/docker/k8s-fssc.yaml` 提供编排样例：Deployment + Service + 探针。
- **多实例必需**：`FSSC_REDIS_ENABLED=true`（分布式状态）+ 所有实例同一
  `FSSC_JWT_SECRET`（否则表现为"刚登录就被踢"）；
- 调度锁在单机模式下用 MySQL GET_LOCK，多实例必须 Redis。

## 2. 配置项全表（.env）

| 变量 | 必填 | 默认 | 说明 |
|---|---|---|---|
| `FSSC_DB_PASSWORD` |  | 无（fail-fast） | 两库共用口令 |
| `FSSC_JWT_SECRET` |  | 无（fail-fast） | ≥32 字节；多实例必须同值 |
| `SPRING_PROFILES_ACTIVE` | | dev | prod 关闭 SQL 日志 |
| `FSSC_DB_MASTER_JDBC_URL` / `FSSC_DB_IMAGE_JDBC_URL` | prod 必填 | 空即建池失败 | **只有 prod profile 读这两个键**；`dev` 的连接串写死在 `application-dev.yml`（127.0.0.1:3306），跨机/容器部署必须走 prod |
| `FSSC_DB_USERNAME` | | root | |
| `SERVER_PORT` | | 8089 | |
| `FSSC_API_TARGET` | | http://127.0.0.1:8089 | 前端 preview 反代目标 |
| `FSSC_REDIS_ENABLED` | | false | 多实例必须 true |
| `FSSC_OCR_CHANNEL` | | gateway | mock/gateway/paddle/http；`mock`（确定性模拟票面）需显式设置，出厂默认走发票网关 |
| `INVOICE_GATEWAY_ENABLED` | | true | 发票网关在 FSSC 侧总开关；离线演示必须置 false，否则首启日志一片通道失败 |
| `INVOICE_GATEWAY_BASE_URL` / `INVOICE_GATEWAY_API_KEY` | | 8096 / 空 | 网关地址与密钥 |
| `FSSC_BANK_GATEWAY` | | mock（缺省即 mock） | 置 `http` 才切 HttpBankGateway |
| `FSSC_BPMN_REPO_DIR` | | ./bpmn-repo | 流程模型 git 工作副本 |

**铁律：口令/密钥类无默认值，留空启动失败是有意的**；生产凭据禁入库、禁进镜像层。

## 3. 健康检查与监控

- 存活/就绪探针：`/actuator/health/liveness`、`/actuator/health/readiness`
  （免鉴权，给 k8s 探针用）；
- 优雅停机：`server.shutdown=graceful`（30s 窗口）；
- 日志：`fssc/fssc-server/logs/`（按日切割，**不入库不进镜像**）；
- 关键业务监控抓手：`op_sla_breach`（SLA 违约）、`op_stability_log`（卡单率）、
  `wf_task` 停留时长（节点卡点）、`pf_oper_log`（操作审计）。

## 4. 备份策略

| 对象 | 方式 | 频率建议 |
|---|---|---|
| 主库 `fssc` | mysqldump --single-transaction（含 routines/triggers/events） | 每日 + 变更前 |
| 影像库 `fssc_image` | 同上（数据增长快，可只备结构 + 近期数据） | 每日 |
| 影像文件 | `fssc/fssc-server/data/files/` 目录同步 | 实时/每日 |
| 流程模型 | `bpmn-repo/` 是 git 工作副本，天然有版本 | 持续 |
| 配置 | `.env`（不进库！进密钥管理系统） | — |

恢复演练每季度至少一次：备份 → 空库导入 → 起服务 → 抽查关键单据。

## 5. 升级流程

1. 停服务（先停看门狗/守护进程，再停后端，`netstat` 复核端口）；
2. 备份两库；
3. 执行 `sql/` 下新版本迁移脚本（V 系列按序，**每步留执行记录**）；
4. 替换 jar（**先移走旧 jar 再打新包**，否则 maven 判"jar 比 classes 新"跳过重建，
   打出假新包）；
5. 起服务 → 健康检查 → 冒烟（登录/提单/审批/凭证）；
6. 挂回看门狗。

**校验新包的唯一标准是 zip 内 class 时间戳与新增端点字符串**，不看 jar 大小/mtime。

## 6. 常见运维事故与对策

| 事故 | 根因 | 对策 |
|---|---|---|
| 重启后新端点 404 | 用了旧 jar | 按 §5 第 4 步校验 class |
| 服务被静默杀死 | 无看门狗 | 挂看门狗 + 就绪探针 |
| "刚登录就被踢" | 多实例 JWT_SECRET 不一致 | 统一注入 |
| 归档失败 | 冷热表列序不一致 | 加列同步冷表后重跑 |
| 配置改了不生效 | node_key 是孤儿行 | 对照已部署 BPMN 核对 |

## 7. 多租户运维必读（2026-11-03 增补，对应 SaaS 整改清单 P0/P1）

### 7.1 开租户前必配项

| 配置项 | 缺省 | 不配的后果 |
|---|---|---|
| `fssc.tenant.init-admin-pwd` | 空（fail-closed） | 审核通过直接被拦，租户无法开通 |
| `fssc.self-registration.enabled` | `false` | 企业自助注册入口关闭（默认按规范关闭） |

开通时会自动执行「角色 + 编号规则」最小模板：
`ADMIN / FIN_MANAGER / EMPLOYEE` 三角色、8 条单据编号规则，管理员自动挂 ADMIN。
其余模板（组织/账簿/科目/流程默认值）按域分批立项，**不在开通里自动造**。

### 7.2 套餐功能变更的生效延迟

套餐矩阵改动经登录写入 JWT claim `ftr`，**存量会话需重新登录才生效**（与 RBAC 权限缓存同因）。
给客户改套餐后，请提示其重新登录；不要按"改完就变"对外承诺。

### 7.3 Flowable 引擎租户隔离的上线顺序（破坏性窗口）

引擎租户隔离的代码与回填 SQL **必须同窗**：

```
停服 → 跑 V1.6.05 回填（21 张 act_*/flw_* 的 TENANT_ID_）→ 上新包 → 冒烟
```

- 先迁后码：旧包按无租户查定义，查不到已回填的定义，提单全断；
- 先码后迁：新包按租户查定义，历史定义仍是空租户，同样断。
- 冒烟必须含「新建一笔报销走到办结」，不只看服务起没起来。
- 回填前请确认 `act_ru_execution` / `act_ru_task` / `act_hi_procinst` 的在办/历史行数
  （本机现盘 0 行；若线上有在办实例，先在窗口内跑完再回填）。

### 7.4 跨租户读取边界

平台端读跨租户**明细**的唯一出口是 `TenantExportService`（`@PlatformOnly` + 按 `tenant_id` 显式过滤
+ 每表 5 万上限）。平台看板只允许 `sum/count` 聚合。

`runIgnoreTenant` 使用点已建立基线（`scripts/health/ignore_tenant_baseline.json`，54 个方法），
新增使用点必须登记后提交：

```bash
python scripts/health/ignore_tenant_registry.py --check   # 有未登记新增即红
```

### 7.5 多租户巡检脚本

| 脚本 | 作用 | 期望 |
|---|---|---|
| `scripts/health/tenant_registry_tool.py --check` | 表口径三处一致性 + 缺列清单 | 全绿（已知缺陷清空后应为 0 张） |
| `scripts/health/check_jdbc_tenant.py --probe` | 裸 JDBC 是否自证租户条件 | 全绿（豁免逐条打印） |
| `scripts/health/ignore_tenant_registry.py --check` | runIgnoreTenant 增量 | 全绿 |
| `scripts/health/check_tenant_coverage.sql` | 库结构巡检（由登记表生成） | D2-01/02/03 均 0 行；D2-04 两张 `sod_*` 为 `HAS_COLUMN` |

> 登记表有两个区：`globalTables`＝**没有** `tenant_id` 列的全局表；`globalTablesWithTenantColumn`＝
> **有列但要求拦截器免加等值谓词**的表（`sod_role_conflict`/`sod_perm_conflict` 的 `tenant_id` 可空，
> NULL 表示平台级规则，必须由 `SoDService` 手工按 `(NULL OR 当前租户)` 取）。两区都要进 Java 白名单。

### 7.6 预提/待摊与预算的联动

`ACCRUAL`（费用预提）/`DEFER`（费用待摊）记账单**提交即占预算**，冲销/驳回/撤回即释放，
口径对齐参照 ERP的预算影响类型（申请占用 / 预算冲回）。**两条口径可配**（预算管理 → 预算口径）：

| 开关 | 系统参数键 | 缺省 | 关闭后 |
|---|---|---|---|
| 预提/待摊占用预算 | `budget.accrual.occupy.enabled` | 开 | 只做会计确认，不进预算；单据显示「按配置不占」 |
| 合同占用预算 | `budget.contract.occupy.enabled` | 开 | 合同只查余额不锁额度（弱控） |

缺省为开＝升级后行为不变；**关闭不追溯**（已占额度仍在冲销/关单时释放）。

运维须知三条：

1. **占不满不等于没预算**：单据上 `budget_occupy_status` 有四态，
   `OCCUPIED` 已占用 / `RELEASED` 已冲回 / `NONE` 该占却没找到预算明细（黄色「未占预算」）/
   `DISABLED` 按口径配置不占（灰色「按配置不占」）。**NONE 才是数据缺口**，需要补预算明细或 `md_item_budget_map` 映射。
2. **先冲销预提、再报销**：本版没有「预提→报销」下推关系，参照 ERP靠「单据下推回写」释放已执行部分，
   我方语义等价于「关闭释放」。同一笔费用若先预提、后报销且不冲销预提，会占用两次。
3. **借贷默认科目**：预提默认「借 6602 / 贷 2241 其他应付款」（不是银行存款——预提没付钱）。
   若科目表里 6602 是父级，制单会被直接拦下并提示选末级科目；**不会**等到审批走完才出不了证。
