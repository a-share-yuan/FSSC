# 系统特点

FSSC 的十二项核心特点，按"平台能力 → 业务深度 → 工程品质"排列。
每项都说明**它解决什么问题**与**怎么做到的**。

## 一、平台能力

### 1. 多租户 SaaS 底座
- **问题**：集团下每家企业一套部署，升级一次全员停机。
- **做法**：shared-DB shared-Schema，`tenant_id` 列 + MyBatis 拦截器自动
  重写 SQL，业务代码无感知；租户套餐（`pf_package`/`pf_feature`）控制功能开关，
  登录态里带租户上下文，跨租户访问在拦截层直接掐断。
- **边界**：这是列级隔离，不是物理分库；对安全极限要求的场景可再套一层库级隔离。

### 2. 可视化流程引擎，变更不发版
- **问题**：审批流写死在代码里，加一个节点要发版。
- **做法**：Flowable 8 + bpmn-js 在线设计器；流程模型版本化存于 `bpmn-repo/`，
  设计器里"发布"才生效；`wf_node_config` 把"节点找谁批"从流程定义里解耦成配置，
  支持按角色/维度/灰度白名单取人。
- **注意**：节点配置表的 `node_key` 必须命中已部署 BPMN 的 userTask id，
  否则是永不生效的孤儿行——部署后要用脚本核对。

### 3. 三层权限模型
- **RBAC**：用户→角色→菜单/按钮（`sys_user_role`/`sys_role_menu`）。
- **套餐特性**：`perms ∩ features`，套餐没买的功能连接口都进不去。
- **数据范围**：按公司/部门/项目维度裁数据，A 公司的人看不见 B 公司的单据。
- 详见 [权限体系](权限与多租户.md)。

### 4. 全链路联查
任意业务单据可正向/反向追溯：报销单→审批记录→发票影像→付款单→银行流水→
会计凭证→总账余额，反向亦可。时间线的唯一真相是流程引擎的 `chain.summary`，
不让各业务表各说各话。

## 二、业务深度

### 5. 费用报账全家桶
事前申请、差旅、借款核销、分摊、事前/事中管控、超申请走长审批；
费用政策（标准/职级/城市）驱动合规预检，超标自动升级审批链。

### 6. 应收应付闭环
- **应付**：采购订单→收货→发票→三单匹配（容差可配）→结算单→付款批次→
  资金执行→付款凭证，匹配不齐直接拦截并给出补齐指引。
- **应收**：对账→开票（发票规则按客户配置）→应收确认→收款核销→坏账处理。

### 7. 资金与银企
资金计划、付款批次（组批/拆批）、银行余额、银行对账（自动+手工）、
票据（应收/应付票据）全生命周期；银企直连走 SPI，默认 mock 离线演示。

### 8. 影像与发票
影像采集批次化，OCR 通道可插拔（mock / 网关 / 本地 PaddleOCR / 任意 HTTP 引擎），
发票查验留痕，档案装订销毁有审批，全程与业务单据挂接。

### 9. 共享作业运营
派工规则、作业排班、SLA 超时升级、质量抽检、复核、稳定性看板——
把"共享中心"当生产线管理，而不是一堆待办列表。

### 10. 总账与月结
多账簿、多币别、期末结转（汇兑/损益）、月结检查清单（试算平衡才给关账），
凭证从业务单据自动生成，也可手工/合并生成。

## 三、工程品质

### 11. 元数据驱动，运营改词不发版
字典（域字典/展示字典/状态展示）三层收口，下拉与列表展示统一取词；
表单字段与校验规则由表结构反射生成（`md_form_field`/`md_form_validation`）；
打印模板、导入导出模板全部入库（毫米坐标套打、逐行错误清单不中断整批）。

### 12. 闸门都是"正确拦截"
金额改动七处冗余联动、三单匹配拦截、齐套闸口、同人连办拦截、职责分离（SoD）
检查——每个闸门拦截时都告诉用户"缺什么、去哪补"，而不是甩一句系统异常。

## 设计取舍（诚实清单）

| 取舍 | 说明 |
|---|---|
| 界面中文单语 | 无 i18n 框架，`src/i18n/` 仅 bpmn-js 画布补丁；本地化是独立工程 |
| 源码发布 | 前端包 `private: true`，不发布 npm 包，不提供托管 demo |
| JDK 26 | 锁定非 LTS 版本换取最新语言/框架特性，迁移 LTS 需重验构建 |
|  | 主体代码 后经长期人工业务演练加固；文档标注了哪些是实测、哪些是读码结论 |
