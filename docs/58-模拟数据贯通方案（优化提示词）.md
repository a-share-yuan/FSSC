# FSSC 全量模拟数据 · 贯通方案（优化提示词 + 设计）


---

## 一、原诉求 → 优化后提示词（可直接复用）

**优化版提示词：**

> 为 FSSC 财务共享平台生成一套**端到端贯通的演示数据**，要求：
> 1. **底座必须真实**：公司、部门、角色、用户、供应商、项目、科目、银行账户等主数据一律复用库内已有真实记录，**不得臆造**；新建交易单据的外键必须 ∈ 现有主数据。
> 2. **角色用户必须来自流程配置**：每张单据的「发起人 / 审批人 / 共享作业人员」一律取自 `wf_business_flow → wf_node_config` 的节点指派（`assign_type=ROLE` 时按 `assign_value` 角色编码经 `sys_role.role_code → sys_user_role → sys_user` 解析；`assign_type=USER` 直接用指派用户；`INITIATOR` 为制单员工）。**严禁在节点角色之外随便填一个用户名**。
> 3. **七大域联动贯通**：预算、费用报销、采购与应付、发票、影像、共享运营、总账与资金，数据必须互相引用同一业务单号（`biz_no`）形成闭环，而不是各域孤立造数。
> 5. **每页有数、可追溯**：左侧每个菜单页面列表非空；并产出「全量结构与人机核验手册」，记录域/公司/部门/角色/用户/菜单/入口/流程节点角色用户映射，供人工逐页核验。
> 6. **可回滚**：所有落数脚本产出 `_rollback_*.json`，支持逆向删除，不影响既有数据。

## 三、七大贯通域 × 核心数据脊柱

### 脊柱 A：费用报销一条龙（用户原话示例）
```
员工(INITIATOR) ──发起──> 事前申请(TRAVEL/MEETING/TRAIN)
        │ 预算占用(bg_occupy OCCUPY on bg_item)
        ▼
员工费用报销 / 差旅培训报销 (CLAIM / CLAIM_TRAVEL)
        │ 上传发票附件 → sys_file
        ▼
影像采集 img_batch + OCR(img_file/ocr_record)  ←─ 发票管理 inv_invoice + inv_verify_log
        │ 共享任务池 dispatch_task 抢派单 → op_quality 质检
        ▼
审批流 wf_instance/wf_task（审批人取自节点 ROLE 真实用户）
        │ 过账核销(bg_occupy WRITE_OFF)
        ▼
共享凭证 op_voucher + op_gl_entry（借贷：费用/应付/银行）
        │
        ▼
付款 op_pay_batch → 银企直连 → op_bank_statement → bank_reconcile
        │
        ▼
电子归档 op_archive → 借阅/销毁档案链
```

### 脊柱 B：采购与应付一条龙
```
合同 cont_contract ──> 采购订单 po_order ──> 收货 po_receipt
        │
        ▼
进项发票 inv_invoice(发票池) + 验真 inv_verify_log + OCR
        │ 三单匹配(订单/收货/发票) match_tolerance
        ▼
应付确认 → 付款计划 pay_plan → 付款服务申请 ap_service_request
        │ 审批(节点 ROLE 用户)
        ▼
付款批次 op_pay_batch → 供应商对账 supplier_recon → 银企对账 bank_reconcile
```

## 四、落数方法论（强制规则）

1. **主数据零新增原则**：公司/部门/角色/用户/供应商/项目/科目/银行账户/费用项全部复用；如需演示新增，只允许在「演示专用」标记下补充，且外键闭环。
2. **流程角色唯一来源**：造单前先查 `wf_node_config` 解析该 `biz_type` 的真实审批链；`wf_task.assignee` 必须是解析结果中的用户。
3. **外键完整性**：每张业务表 `company_id/dept_id/biz_no/create_by` 必须落在第 1~4 节清单内。
4. **状态机一致**：单据状态与流程实例状态对齐（草稿/审批中/通过/付款/归档）。
5. **可回滚**：每次落数先 dump 待删主键到 `_rollback_*.json`，逆向脚本按主键删除。

## 六、执行顺序（建议）

1. **先打通脊柱 A（费用一条龙）**：单家公司（建议湖南分公司 AIG-HN）覆盖 预算→报销→影像→发票→共享凭证→付款→档案，证明闭环。
2. **再打通脊柱 B（采购应付一条龙）**：同公司覆盖 合同→订单→收货→发票→三单匹配→付款→对账。
3. **横向铺满 7 域页面**：在各域菜单页面补齐列表数据，确保左侧每页非空。
4. **产出核验报告**：逐页统计 + 闭环追溯。
